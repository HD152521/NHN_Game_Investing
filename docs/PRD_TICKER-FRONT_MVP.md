## 1. 개요

### 1.1 제품 한 줄 정의

**정체를 가린 실제 과거 거래일 차트를 읽어 전쟁 자금을 만들고, 그 돈으로 일자형 타워디펜스 웨이브를 막아 지역을 점령하고, 클리어 후 그것이 어떤 회사의 어느 날이었는지 알게 되는 게임.**

### 1.2 MVP의 목적

MVP는 **기능을 많이 만드는 것이 목적이 아니라, 아래 두 가설을 검증하는 도구**다.

| 가설 | 검증 방법 | 통과 기준 |
|---|---|---|
| **H1 — 자금 도착의 쾌감**: 웨이브가 밀려오는 중에 예측이 적중해 골드가 꽂히고, 그 돈으로 급히 타워를 세우는 순간이 재미있다 | 플레이테스트 20명, 세션 후 설문 + 관찰 | "이 순간이 가장 재미있었다" 응답 ≥ 50% |
| **H2 — 공개의 쾌감**: 클리어 후 "이게 그 회사 그 날이었어?"라는 반응이 나온다 | 플레이테스트 관찰 (공개 화면에서의 발화·표정) | 소리 내어 반응한 인원 ≥ 60%, 공개 화면 평균 체류 ≥ 20초 |

### 1.3 성공 기준 (정량)

| 지표 | 목표 |
|---|---|
| 튜토리얼 완주율 | ≥ 70% |
| 첫 세션 평균 플레이 시간 | ≥ 15분 |
| 3지역 전체 클리어 도달률 | ≥ 40% |
| D1 재방문율 (테스터 기준) | ≥ 35% |
| 세션당 평균 포지션 수 | ≥ 8개 (예측을 실제로 쓰는지) |
| 공개 화면 스킵률 | ≤ 25% |

### 1.4 킬 크라이테리아 (이 경우 기획을 되돌린다)

- H1·H2 **둘 다** 통과 기준 미달
- 세션당 평균 포지션 수 < 4개 (예측이 무시되고 있음 = 코어 설계 실패)
- 테스터의 50% 이상이 "차트를 볼 시간이 없다"고 응답 (리듬 설계 실패 → 준비 페이즈 재설계 필요)

### 1.5 비목표 (Non-goals)

- 실제 투자 교육 도구가 되는 것 (부수 효과일 뿐, 목표 아님)
- 실시간 시세 반영 (MVP 범위 밖)
- 수익화 검증 (MVP는 결제 없음)
- 멀티플레이

## 2. 타겟 유저

| 페르소나 | 설명 | MVP에서의 니즈 |
|---|---|---|
| **P1 · 타워디펜스 팬 (주 타겟)** | Age of War·Bloons 계열을 즐긴 20~30대. 주식은 잘 모름 | 예측이 어렵지 않게 느껴져야 함 → 튜토리얼과 R1 난이도가 결정적 |
| **P2 · 주식·코인 관심층** | 차트를 볼 줄 알고 종목을 아는 20~40대 | 차트가 진짜 데이터라는 신뢰, 공개 화면의 정보 밀도 |

**MVP는 P1을 1순위로 잡는다.** P1이 예측 앞에서 좌절하면 아무것도 검증되지 않는다.

## 5. 기능 요구사항

표기: `[P0]` 필수 / `[P1]` 있으면 좋음 / 수용 기준은 Given-When-Then.

---

### FR-1. 계정 & 저장 `[P1]`

**FR-1.1** 최초 접속 시 로그인 없이 **익명 계정(UUID)** 을 자동 발급하고 localStorage에 토큰을 저장한다.
**FR-1.2** 모든 진행도(자본금, 점령 지역, 부서 레벨, 도감)는 **서버에 저장**한다. 클라이언트 저장은 캐시일 뿐 권위가 없다.
**FR-1.3** 진행도 저장은 다음 시점에 발생: 스테이지 정산 완료, 점령 보상 선택, 부서 업그레이드.
**FR-1.4** 토큰 유실 시 진행도 복구는 지원하지 않는다 (MVP 한정, 화면에 명시).

**수용 기준**
- Given 최초 방문자 / When 페이지 진입 / Then 로그인 UI 없이 즉시 인트로가 시작되고 서버에 계정 1건이 생성된다
- Given 정산 완료 / When 브라우저를 새로고침 / Then 자본금·점령 상태가 유지된다

---

### FR-2. 세계지도 & 지역 선택 `[P0]`

**FR-2.1** MVP 지도는 **대한민국 3지역**만 표시한다.

| ID | 지역 | 섹터 | 차트 풀 | 인접 |
|---|---|---|---|---|
| R1 | 여의도 | 금융 | 은행·증권·보험 | (시작점) |
| R2 | 판교 | IT·플랫폼 | 게임·인터넷·SW | R1 |
| R3 | 울산 | 중공업·에너지 | 조선·정유·자동차 | R2 |

**FR-2.2** 지역 상태는 `잠김 / 도전가능 / 점령` 3가지. **인접 지역을 점령해야 다음 지역이 `도전가능`** 이 된다.
**FR-2.3** 각 지역 노드에 표시: 지역명, 섹터, **난이도 등급(★1~3)**, 점령 여부, 획득한 점령 보상 계열 아이콘.
**FR-2.4** 점령한 지역도 재도전 가능. 재도전 시:
  - 같은 섹터의 **다른 종목×날짜 조합**이 배정된다 (재출현 쿨다운 §FR-3.6)
  - 자본금 정산은 **50%만** 지급 (파밍 방지)
  - 점령 보상은 **아직 획득하지 않은 계열만** 선택 가능
**FR-2.5** 지도 화면에 상시 표시: 자본금, 점령 지역 수, **현재 운영비**, **현재 경계도 계수**.

**수용 기준**
- Given R1 미점령 / When R2 노드 클릭 / Then "인접 지역을 먼저 점령하세요" 안내가 뜨고 진입 불가
- Given R1 점령 & 재무 계열 이미 획득 / When R1 재도전 클리어 / Then 재무 계열이 선택 목록에서 비활성 표시된다

### FR-3. 차트 리플레이 엔진 `[P0]` ★ 코어

**FR-3.1 시간 매핑**

```
1 게임초 = 1 실거래분
1 스테이지 = 실제 1거래일 = 390분 = 390초 = 6분 30초
1 웨이브 = 30초 = 실제 30분봉 1개 → 총 13웨이브
웨이브 사이클 = 준비 10초 + 웨이브 진행 20초
차트는 준비 페이즈에도 계속 흐른다 (일시정지 없음)
```

**FR-3.2** 스테이지 데이터는 **1분봉 OHLCV 390개**로 구성된 정적 파일이며, 스테이지 시작 시 **전량 프리로드**한다 (스트리밍 안 함).
**FR-3.3** 화면 렌더는 1분봉 사이를 **선형 보간**해 초당 60프레임으로 부드럽게 그린다. 보간은 **표현 전용**이다.
**FR-3.4** 예측 판정은 **반드시 실제 1분봉 종가**를 사용한다. 보간값으로 판정하면 안 된다. (판정은 서버가 수행 — FR-5)
**FR-3.5** 배속 옵션 `0.5x / 1x / 2x`. 배속 변경은 **스테이지 시작 전에만** 가능하고 진행 중 변경 불가 (판정 일관성).
**FR-3.6 조합 쿨다운**: 한 번 플레이한 `종목×날짜` 조합은 해당 계정에서 **20회 플레이 동안 재출현하지 않는다.**
**FR-3.7 진행 표시**: 상단에 `09:00 ─●────── 15:30` 시각 진행 바. **시각은 보여주고 날짜는 숨긴다.**

**수용 기준**
- Given 1x 배속 / When 스테이지 시작부터 종료까지 / Then 총 경과 시간이 390초 ± 2초다
- Given 임의 시점에 청산 요청 / When 서버가 청산가를 확정 / Then 그 가격이 **서버 재생 시각 기준 보간가**와 일치하며, 클라이언트가 보낸 값과 무관하다 `[v1.2]`
- Given 동일 계정으로 R1을 3회 플레이 / Then 세 번 모두 다른 종목×날짜 조합이 배정된다

### FR-5. 포지션 시스템 `[P0]` ★ 코어

> **v1.2 — 만기제 폐기.** 15/30초 만기 판정 구조를 **자유 매매제**로 전면 교체했다.
> 플레이어는 LONG/SHORT로 **언제든 진입하고 언제든 청산**한다. 만기는 존재하지 않는다.
> 폐기 사유와 대체 설계의 근거는 이 절 하단 **FR-5.12 설계 노트** 참조.

**FR-5.1 UI 구성** — 차트 패널 하단에 고정. 보유 상태에 따라 두 형태로 전환된다.

```
[미보유]   [ LONG ▲ ]  [ SHORT ▼ ]      투입:  10%   25%   50%   ALL
[보유중]   LONG · 500  │  평가손익 +138 G  │  청산선까지 −0.42σ  │  [ 청산 ]
```

**FR-5.2** 동시 보유 포지션은 **1개**로 제한한다 (MVP). 보유 중에는 신규 진입 버튼이 비활성이다. **`[v1.3]` 추가 매수(물타기·불타기)는 지원한다** (FR-5.2-a). **부분 청산은 여전히 미지원**이다.

**FR-5.2-a 추가 매수** `[v1.3 신규]`

```
addStake  = floor(현재 AUM × stakeRatio)
addFee    = round(addStake × FEE_RATE)                                   # 추가분에도 수수료
newStake  = stake + addStake
newFee    = fee + addFee                                                 # 누적
newPrice  = (stake × openPrice + addStake × 현재가) / newStake            # stake 가중 평균 단가
AUM      -= addStake
```

- 방향은 바꿀 수 없다. 추가 매수는 항상 기존 포지션과 같은 방향이다.
- `liqLine`·`openAtMs`·`seq`는 **최초 진입 값을 유지**한다 — 추가 매수로 최소 보유 시간이 리셋되면 안 된다.
- 추가 매수도 **진입 횟수(`MAX_POSITIONS`)를 소모**한다.

> **★ 평균 단가가 움직이면 강제 청산선도 밀린다. 이건 부작용이 아니라 이 기능의 설계 목적이다.**
> `evaluatePosition`이 `deltaPct`를 평균 단가 기준으로 계산하므로, 손실 중에 추가 매수하면
> 평균 단가가 현재가 쪽으로 당겨져 `z`의 절대값이 줄고 `r`이 청산선에서 멀어진다.
> 다음 사람이 "버그 아닌가?" 하고 되돌리지 않도록 명시한다.
>
> **실측 예시**: AUM 2000 → 100에 LONG 25%(stake 500). 가격 90으로 하락 시 `r = −0.90`
> (청산선 −1.00 코앞). 여기서 AUM의 50%(750)를 90에 추가하면 평균 단가가 94가 되어
> `r ≈ −0.383`, 청산까지 여유가 **0.10 → 0.617**로 넓어진다.
>
> **대가**: 여기 들어간 AUM은 골드로 바꿔 타워를 세울 수 있었던 자원이다.
> **버티면 방어가 얇아지고, 방어가 뚫리면 AUM 보충(적 처치 드롭)도 끊긴다.**
> 이 트레이드오프가 매매와 전투를 실제로 맞물리게 하는 장치다.
**FR-5.3** 스테이지당 최대 **진입** 횟수 `MAX_POSITIONS` = 24회. 청산은 횟수에 포함하지 않는다.
**FR-5.4 가격 결정 (진입·청산 공통)**: 진입가와 청산가는 모두 **서버가 자기 시계로 계산한 해당 재생 시각의 가격**이다. 클라이언트가 보낸 가격·시각은 어떤 경우에도 신뢰하지 않는다. 서버 재생 시각과 클라이언트 요청 시각의 차이가 `POSITION_LATENCY_TOLERANCE`(1.5초)를 넘으면 요청을 거부한다.
**FR-5.5 손익 수식** — 청산 시점에 확정된다.

```
방향부호 s  = LONG이면 +1, SHORT이면 −1
Δ%         = s × (청산가 − 진입가) / 진입가 × 100
σ          = 해당 조합의 사전 계산된 30분 구간 수익률 표준편차 (스테이지 데이터에 포함)
z          = Δ% / σ                            # 부호를 유지한다 (음수 가능)

수익배율 r  = B × clamp(z, −Z_MAX, +Z_MAX)      # B = 0.90, Z_MAX = 3.0
수수료 fee = stake × FEE_RATE                   # 진입 시 1회, FEE_RATE = 0.01
순손익 pnl = stake × r − fee
```

**FR-5.6 강제 청산 (마진콜)** — 평가 기준 `pnl ≤ −stake`가 되는 순간 서버가 **자동으로 청산**하고 `pnl = −stake`로 확정한다. 즉 **손실은 원금을 초과하지 않으며, 원금 전액 소실이 최대 손실**이다.

```
강제 청산 발동선  r ≤ −LIQUIDATION_LINE       (LIQUIDATION_LINE = 1.0)
법무팀 부서가 이 선을 완화한다 (FR-11.2)
```

강제 청산은 **경고 없이 즉발하지 않는다.** 발동선의 80%에 도달하면 UI가 적색 경고 상태로 전환되고 경고음이 1회 재생된다.

**FR-5.7 전액 골드 이관 정산** `[v1.3 개정]` — 청산 시 정산은 다음 규칙을 따른다.

```
진입 시:  AUM −= stake                                       (수수료는 stake에서 선차감)
청산 시:  골드 += floor(max(stake + pnl, 0) × GOLD_CONVERSION)  ← 대금 전액이 골드가 된다
          AUM 증가 없음                                        ← 원금 복귀 경로 자체가 없다

GOLD_CONVERSION = 0.50
```

> **AUM은 골드로 흐르는 일방통행 파이프다.** 매매를 잘하면 같은 AUM에서 더 많은 골드가
> 나오고 못하면 덜 나오지만, 어느 쪽이든 AUM에서 빠져나가 골드가 된다.
> **AUM을 다시 채우는 유일한 경로는 적 처치 드롭**(FR-6.8-a)이다.
> 강제 청산 시 `pnl = −stake`이므로 대금이 0이 되어 골드 증가도 정확히 0이다.
>
> ⚠️ **v1.2의 "원금-이익 분리"(`aumReturned`)는 폐기되었다.** 그 규칙은 세탁을 막기 위한
> **땜빵이었고 개념이 어긋나 있었다** — 투자를 했으면 결과는 전부 골드가 되어야지, 원금
> 일부가 다시 매매 재화로 돌아올 이유가 없다. 부수 문제도 있었다: 원금이 복귀하면 AUM이
> 재순환해 세션 총 투입액이 시작 AUM의 5~6배로 불어나고, 그 배수가 밸런스의 숨은 변수가 됐다.
>
> **세탁을 막는 장치는 이제 `GOLD_CONVERSION` 하나다.**
> ① 무판단 전환(z≈0)은 대금이 `stake × 0.99`이므로 투입액의 **49.4%**만 골드가 된다.
> ② 원금이 돌아오지 않으므로 **같은 AUM을 두 번 굴릴 수 없다** — 세탁은 1회성 행위다.
> ③ 따라서 세탁 골드의 상한은 `S × 0.99 × 0.50`으로 못 박히고, R1에서 2,267 G로
>    필요지출 2,700 G에 닿지 못한다(§9.3 검산표).
>
> **세션 총 투입액 S는 이제 파생값이다**: `S = 시작 AUM + AUM_DROP_PER_WAVE × 13`.
> 청산이 AUM을 늘리지 않으므로 "세션 동안 굴릴 수 있는 총액 = 세션 동안 받은 AUM 총액"이
> 항등식으로 성립한다. **AUM 유입 경로는 적 처치 드롭 하나뿐이며, 매매로는 절대 늘지 않는다** —
> "매매를 적게 할수록 AUM이 쌓인다"는 v1.2의 역인센티브가 여기서 사라진다.

**FR-5.8** AUM은 **포지션 투입과 `S-03` 시전 외의 용도로 사용할 수 없다.** 골드로 직접 전환하는 기능은 존재하지 않으며, 골드로의 유일한 전환 경로는 **포지션을 열고 닫는 것**이다 — 즉 반드시 시장 리스크를 한 번 통과해야 한다.
AUM의 획득 경로는 **① 스테이지 시작 시 지급**(부서 레벨 기준)과 **② 적 처치 드롭**(FR-6.8-a) 두 가지다.
**FR-5.9 보유 중 표시** — 차트 위에 진입 지점 마커와 **강제 청산 가격선**을 상시 렌더한다. HUD에는 평가손익(골드 환산)과 청산선까지 남은 거리를 σ 단위로 표시한다. 평가손익은 **250ms 주기**로 갱신한다.
**FR-5.10 청산 연출** — 이익 청산은 **골드(`#FFC53D`)**, 손실 청산은 **청색(`#2E86FF`)**, 강제 청산은 적색 강조 + 별도 문구. `[v1.3 개정]` ⚠️ **초록을 쓰지 않는다** — 아트가이드 §1.3의 확정 팔레트에 초록이 없고, 한국식 `상승=적 / 하락=청` 체계에서 초록을 끼우면 차트색과 진영색이 같은 시스템이라는 전제가 깨진다. **연출은 0.8초 이내**로 짧게 (전투 흐름을 끊지 않아야 함).
**FR-5.11 레이트 리밋** — 진입·청산 각각 초당 최대 1건만 허용한다 (봇 방지). 또한 진입 후 `MIN_HOLD_SEC`(2초) 이내에는 청산할 수 없다.

**FR-5.12 설계 노트 — 만기제를 폐기한 이유와 그 대가**

| 항목 | 만기제 (v1.1) | 자유 매매제 (v1.2) |
|---|---|---|
| 플레이어 결정 | 진입 1회 | 진입 + **청산 타이밍** |
| 주식다움 | 이진 예측(홀짝에 가까움) | **익절/손절 판단이 실제로 존재** |
| 전투와의 병행 | 걸고 잊으면 됨 | **차트를 계속 봐야 함** ⚠️ |
| 최대 손실 | stake 전액 | stake 전액 (강제 청산으로 동일하게 봉인) |

⚠️ **인지 부하가 이 변경의 최대 비용이다.** 만기제는 "걸어두고 전투로 복귀"가 가능했으나 자유 매매제는 차트 주시를 강요하므로 **디펜스:주식 = 6:4 무게중심이 주식 쪽으로 밀릴 위험**이 있다. W7 플레이테스트의 1순위 검증 항목이며, 완화 수단으로 **예약 청산**(목표가·손절가 사전 설정)을 `[P1]`로 둔다. §16 O-10 참조.

**수용 기준**
> ⚠️ `[v1.3 재산출]` 아래 수치는 **`goldGained = floor(max(stake + pnl, 0) × GOLD_CONVERSION)`, `GOLD_CONVERSION = 0.50`, AUM 복귀 없음** 기준이다.
> v1.2의 "이익만 골드 · 원금 70% AUM 복귀"(`REFUND_RATIO`) 수치는 전부 폐기됐다.

- Given AUM 2000, 25% 투입(stake 500), 청산 시 z = +1.0 / Then `r` = 0.90, `fee` = 5, `pnl` = 445 → 대금 945 → **골드 +472**, **AUM = 1500 (변화 없음)**
- Given 같은 조건, 청산 시 z = −0.5 / Then `r` = −0.45, `pnl` = −230 → 대금 270 → **골드 +135**, **AUM = 1500**. 투입 500이 골드 135로 줄었으니 손실은 그대로 아프다
- Given 같은 조건, z가 −1.2까지 하락 / Then `r` = −1.08 ≤ −1.0 이므로 **강제 청산 발동**, `pnl` = −500 → 대금 0 → **골드 증가 0**, AUM = 1500 (stake 전액 소실)
- Given 진입 직후 z ≈ 0에서 즉시 청산 / Then `pnl` = −5(수수료) → 대금 495 → **골드 +247 (투입액의 49.4%)**, **AUM = 1500**. 원금이 돌아오지 않으므로 **이 왕복을 반복할 수 없다**
- Given AUM 전액(2000) 세탁 / Then 골드 +990, AUM = 0 → **재진입이 `INSUFFICIENT_AUM`으로 거부된다**
- Given R1 한 판 내내 세탁만 반복(시작 2,000 + 웨이브 드롭 150 × 13을 받는 족족 z≈0 전환) / Then 총골드 = 315 + 1,952 = **2,267 G**로 필요지출 2,700 G의 84%에 그친다. `aumGate` 도 이익 청산 0회라 정산 자본금 크레딧이 0이다
- Given 어떤 손익 구간에서 청산하든 / Then **AUM은 진입 직후 값과 정확히 같다** — 청산이 AUM을 늘리는 경로는 존재하지 않는다
- Given 포지션 보유 중 / When LONG 버튼 클릭 / Then 버튼이 비활성이고 아무 일도 일어나지 않는다
- Given 진입 후 1초 경과 / When 청산 요청 / Then `MIN_HOLD_SEC` 미달로 거부된다

**FR-6.5-b 스탯은 개체에 실린다** `[v1.3 신규 — 구조 요구사항]`

유닛·적은 `hp` / `maxHp` / `speed`(이동) / `damage`(공격력) / `range`(공격 사거리) / `attackCooldownMs`(공격 주기) / `cooldownMs`(남은 재장전)를 **개체 필드로 갖는다.**

> **종류(`kind`)로 전역 상수 테이블을 조회해 스탯을 쓰지 마라.** 상수 테이블은 개체를
> 만들 때의 **기본값 출처**일 뿐이다.
>
> **이유**: 부서 업그레이드(FR-11)의 R&D `+피해` / 인사팀 `+HP`는 **개체마다 다른 스탯**을
> 요구한다. `kind`로 조회하면 같은 종류 유닛이 전부 같은 값을 가질 수밖에 없어 이 기능을
> 표현할 수 없다. "진행 중 부서 업그레이드가 이미 소환된 유닛에 소급되지 않는다"는
> 스냅샷 요구사항도 개체 스탯이라야 성립한다.
>
> **부서 업그레이드 훅 지점**: `summonUnit`(유닛) / `buildTower`·`upgradeTower`(타워)에서
> 개체를 만들 때 해당 필드에 배수를 적용하면 된다. 교전 로직은 손댈 필요가 없다.

적의 공격도 타워·유닛과 동일한 **쿨다운 기반 이산 공격**으로 통일했다 (`ENEMY_DAMAGE` 9 / `ENEMY_ATTACK_COOLDOWN_MS` 1000ms = 기존 연속 9 DPS와 동일).

**FR-6.5-a 원거리 교전 규칙** `[v1.3 신규]`
- 유닛은 `gap = 적.x − 유닛.x`가 자기 사거리 이내로 들어오면 **전진을 멈추고 공격**한다.
- 적은 **밀착 거리**(`UNIT_MELEE_RANGE`)까지 와야 반격할 수 있다.
  → 원거리 유닛은 접근 중인 적을 **일방적으로 때리는 구간**을 갖는다. 이것이 이 유닛의 존재 이유다.
- 유닛 정렬은 x 내림차순, 동률이면 **사거리가 짧은 유닛(근거리·탱커)을 앞에 배치**한다.
  → 탱커가 먼저 적과 붙어 원거리를 보호하는 구도가 자동으로 만들어진다.
- **원거리 유닛도 공중 적은 공격할 수 없다** (FR-6.2). 공중은 대공 포대 전용이다.

> **밸런스 검증 결과** (동일 예산 360 G 투입, 웨이브 10~13급):
> 특정 유닛이 항상 정답이 되지 않으며, 탱커+원거리 조합은 단일 종류와 같은 성과를
> **유닛 손실 없이** 달성한다(웨이브 10급에서 5/5 전원 생존 vs 원거리 단독 6기 중 3기 전사).

**FR-6.6 스킬 1종**: `공시 폭탄` — 200 G, 화면 전체 지상 적에게 즉시 피해, 쿨다운 45초.

**FR-6.7 웨이브 구성**: 13웨이브. 웨이브 `w`의 적 스펙:
```
적 수    = ceil(baseCount[w] × heat)
적 HP    = baseHP[w] × heat
적 이동속도 = baseSpeed[w]
heat (경계도 계수) = 1 + (점령 지역 수 × 0.02)
```
`baseCount` / `baseHP` / `baseSpeed`는 지역별 데이터 테이블로 관리한다 (§9.3).

**FR-6.8 기본 수입**: 각 웨이브 시작 시 골드 지급.
```
총 기본 수입 = 25 × 13 − (점령 지역 수 × 25)        ← 이것이 권위 있는 값
웨이브당 지급 = floor(총 기본 수입 / 13)
마지막 웨이브(13) = 총 기본 수입 − (웨이브당 지급 × 12)   ← 나머지 보정
```
> 반드시 총액을 먼저 확정하고 웨이브에 분배한다. 웨이브당 값을 먼저 내림 계산하면 총액이 §9.3 설계치와 어긋난다.
> 예) 점령 2개 → 총 275 G, 웨이브 1~12 각 21 G, 웨이브 13은 275 − 252 = 23 G

**FR-6.8-a AUM 드롭** `[v1.1 신규]`: **적 1체를 처치할 때마다 AUM을 획득**한다.

```
웨이브 w의 적 수  = ceil(baseCount[w] × heat)          ← FR-6.7과 동일한 값
개체당 AUM 드롭   = floor(AUM_DROP_PER_WAVE / 웨이브 w의 적 수)
```

- **웨이브당 AUM 드롭 총량을 상수로 먼저 고정하고, 그 웨이브의 적 개체 수로 나눠 분배한다.**
  개체당 고정 드롭으로 설계하면 후반 웨이브(적 수·heat 증가)에서 AUM이 폭증해
  환율 밸런스가 붕괴한다. 총량 고정이 이 설계의 핵심이다.
- **처치하지 못한 적의 몫은 지급하지 않는다.** 본진을 통과하거나 살아남은 적의
  드롭분은 소멸하므로, 웨이브를 **전멸**시켜야 해당 웨이브의 AUM을 전액 획득한다.
- 나눗셈은 **내림**이므로 개체당 드롭 × 적 수 ≤ `AUM_DROP_PER_WAVE`이다.
  나머지는 버린다(기본 수입 FR-6.8과 달리 나머지 보정을 하지 않는다).
  전멸시켜도 총량에 미달할 수 있으며 이는 의도된 동작이다.
- 적 수가 `AUM_DROP_PER_WAVE`를 초과하면 개체당 드롭이 0이 된다.
  §9.4 웨이브 테이블(최대 14체)과 초기값 150 기준으로는 발생하지 않으나,
  튜닝 시 이 하한을 확인해야 한다.
- 드롭된 AUM은 **즉시 AUM 잔액에 가산**되며 그 웨이브 중에도 포지션 투입에 쓸 수 있다.

> **설계 의도**: v1.0에서 AUM은 스테이지 시작 시 1회 지급되는 소모성 자원이었고,
> 연속 실패는 곧 회복 불가능한 자금 고갈이었다. v1.1에서 AUM을 **전투 성과로
> 재생되는 자원**으로 바꿔, LOSE payout=0(FR-5.5)의 가혹함을 상쇄하고
> "전투를 잘하면 예측 기회가 늘어난다"는 전투↔예측 되먹임 고리를 만든다.

**FR-6.8-b 초기 골드** `[v1.1 신규]`: 스테이지 시작 시 골드를 `STARTING_GOLD` 만큼 지급한다.

- v1.0에서는 골드 시작 지급이 없어 웨이브 1의 기본 수입(약 25 G)만으로 시작했고,
  가장 싼 타워(기본 포탑 120 G)조차 즉시 지을 수 없었다.
- `STARTING_GOLD = 120`은 **기본 포탑 정확히 1기, 잔액 0**을 의도한 값이다. `[v1.3 개정, 기존 200]` 2기째 자금은 첫 청산에서만 나온다 — "매매를 해야 방어가 선다"는 압박을 첫 30초부터 건다.
  **타워 최소 1기는 웨이브 1 이전에 반드시 건설 가능해야 한다**는 것이 이 상수의 제약이다.
- 초기 AUM 지급은 기존 로직(부서 트레이딩데스크 레벨 기준, §9.2 `AUM_BY_DESK_LV`)을 그대로 유지한다.
- `STARTING_GOLD`는 정산의 `총 획득 골드`(FR-8.1 잔여골드율 분모)에 포함된다.

**FR-6.9 패배 조건**: 본진 HP 0. 패배 시 정산 없음, 자본금 0, 도감 등록 없음. **단 공개 연출은 보여준다** (실패해도 정체는 알려줘야 재도전 동기가 생김).
**FR-6.10 승리 조건**: 13웨이브 방어 완료. 적 본진 파괴는 **선택적 보너스** — 유닛을 우측 끝까지 밀어 적 본진 HP를 0으로 만들면 `공격 계열` 자격이 열린다.
**FR-6.11 일시정지**: 불가. 단 `이탈` 가능하며 이탈 시 패배 처리.

**수용 기준**
- Given 점령 지역 2개 / When 스테이지 진입 / Then 총 기본 수입 = 325 − 50 = 275 G (웨이브 1~12 각 21 G, 웨이브 13 은 23 G), heat = 1.04
- Given 스테이지 진입 / Then 골드가 `STARTING_GOLD` = 120 으로 시작하며 기본 포탑(120 G) 1기를 건설하면 잔액이 0이 된다
- Given `AUM_DROP_PER_WAVE`=150, 웨이브 1의 적 수 3체 / When 3체 전부 처치 / Then 개체당 50 AUM, 합계 150 AUM 획득
- Given `AUM_DROP_PER_WAVE`=150, 적 수 3체 / When 2체만 처치하고 1체를 놓침 / Then 100 AUM만 획득 (놓친 몫은 소멸)
- Given `AUM_DROP_PER_WAVE`=150, 웨이브 13의 적 수 14체 / When 14체 전부 처치 / Then 개체당 floor(150/14)=10 AUM, 합계 140 AUM (나머지 10은 버림, 보정 없음)
- Given 본진 HP 0 / Then 즉시 전투 종료 후 공개 연출 화면으로 이동하며 자본금 0이 표시된다

### FR-7. 시장 이벤트 `[P0]`

**FR-7.1** 리플레이 진행 중 실제 데이터가 조건을 만족하면 이벤트가 발동한다. 발동 시점은 **스테이지 데이터에 사전 계산되어 포함**된다 (런타임 판정 아님 → 연출 타이밍 정확도 확보).

| 이벤트 | 발동 조건 (실제 데이터) | 효과 | 지속 |
|---|---|---|---|
| **패닉 셀** | 직전 15분 수익률 ≤ −1.0σ | 다음 웨이브 적 수 +30%, 이동속도 +20% | 1웨이브 |
| **FOMO 랠리** | 직전 15분 수익률 ≥ +1.0σ | 아군 공격력 +25%, 적 HP +15% | 1웨이브 |

**FR-7.2** 발동 시 화면 상단에 **속보 배너**(2초) + 화면 색조 변화(패닉=적색, FOMO=녹색) + 진동/셰이크 연출.
**FR-7.3** 이벤트는 스테이지당 최대 4회로 제한한다 (연출 피로 방지). 초과 조건은 강도 순으로 상위 4개만 채택.
**FR-7.4** 두 이벤트가 같은 웨이브에 겹치면 나중 것이 앞의 것을 대체한다.

**수용 기준**

### FR-8. 정산 & 점령 보상 `[P0]`

**FR-8.1 정산 수식**

```
잔여골드율 = 잔여 골드 / (총 획득 골드)
적중률    = 이익 청산 수 / 총 청산 수            # v1.2 — pnl > 0 인 청산의 비율

기본 자본금 = 잔여 골드 × 1.0 + 잔여 AUM × 0.15 × aumGate          # v1.3 — 계수 0.5 → 0.15
aumGate   = (pnl > 0 인 청산 횟수 ≥ MIN_PROFIT_CLOSES_FOR_AUM_CREDIT) ? 1 : 0    # v1.3 — 기본값 4
보너스 배수 = 1.0
  + (본진 HP 100%       → +0.20)
  + (적중률 ≥ 0.60      → +0.15)
  + (적중률 ≥ 0.70      → +0.30, 위와 중복 아님 — 상위만 적용)
등급 배수  = S 1.6 / A 1.3 / B 1.1 / C 1.0

최종 자본금 = 기본 자본금 × 보너스 배수 × 등급 배수 × (재도전이면 0.5)
```

> ⚠️ **v1.1 영향 2건 — 수식은 그대로 두되 재검증 대상이다.**
> ① `총 획득 골드`(잔여골드율 분모)에 `STARTING_GOLD` 120 G가 새로 포함된다.
> ② ✅ **`잔여 AUM` 항의 AUM 파밍 유인 — v1.3에서 계수 0.15 + 이익청산 게이트로 차단.**
> AUM이 전투 드롭으로 재생되므로(FR-6.8-a) "예측을 하지 않고 AUM만 쌓아 정산에서 0.5배로
> 환전"하는 전략이 이론상 성립하며, 이는 **"예측을 건너뛴 플레이는 존재할 수 없다"(§9.3)는
> 코어 설계 보증과 충돌**한다.
> **채택한 대응**: `MIN_PROFIT_CLOSES_FOR_AUM_CREDIT`(=4) 미만으로 **이익 청산**한 세션은 잔여 AUM을
> 자본금으로 환산하지 않는다. 정상 플레이어는 영향이 0이고 회피 플레이만 정확히 잘라낸다.
>
> ▸ 다만 이 구멍의 **실제 위험은 당초 평가보다 낮다.** 유닛·타워 소환은 골드로만 가능하고
> 골드는 시작 지급·기본수입·청산 대금 셋뿐이므로(FR-5.7), 매매를 하지 않으면 방어를 세울 수 없고
> 방어가 없으면 적을 처치하지 못해 AUM 드롭도 받지 못한다. **자기 발목을 자기가 잡는 구조**다.
>
> ▸ `[v1.3]` 계수 0.15는 `GOLD_CONVERSION`(0.50)보다 **반드시 낮게** 유지해야 한다. 두 값이
> 뒤집히면 "AUM을 굴리는 것보다 쥐고 정산받는 것이 이득"이 되어 AUM이 파이프가 아니라 창고가 된다.
> 잔존 위험은 `STARTING_GOLD` 120 G로 초반 웨이브를 버티며 드롭만 줍는 저강도 변형이고,
> R1(★1)처럼 압력이 낮은 지역에 한정된다. `aumGate`는 그 잔존 경로까지 봉인하는 장치다.

**FR-8.2 등급 산정** — 아래 점수 합으로 결정.

| 항목 | 점수 |
|---|---|
| 잔여골드율 ≥ 20% | 2점 / ≥ 10% 1점 |
| 적중률 ≥ 65% | 2점 / ≥ 55% 1점 |
| 본진 HP ≥ 90% | 2점 / ≥ 70% 1점 |
| 적 본진 파괴 | 1점 |

`S` 6점 이상 / `A` 4~5점 / `B` 2~3점 / `C` 0~1점

**FR-8.3 점령 보상 자격** — 아래 조건을 만족한 계열이 **선택 가능**해진다.

| 조건 | 계열 | MVP 보상 내용 |
|---|---|---|
| 잔여골드율 ≥ 20% | **재무** | 운영비 −10 G/지역 |
| 적중률 ≥ 65% | **정보** | 리서치 Lv1 해금 (거래량 30분봉 바 표시) |
| 본진 HP ≥ 90% | **방어** | 타워 슬롯 +1 |
| 적 본진 파괴 | **공격** | 유닛 소환 비용 −15% |

**FR-8.4** 자격이 여러 개 열려도 **1개만 선택**한다. 선택하지 않은 계열은 그 지역에서 **영구 포기**된다 (재도전으로만 재획득).
**FR-8.5** 자격이 하나도 없으면 기본 보상만(자본금 + 도감 등록) 지급하고 선택 UI를 건너뛴다.
**FR-8.6** 보상 선택 UI는 각 계열의 효과를 **정확한 수치로** 표시한다.

**수용 기준**
- Given 잔여골드율 25%, 적중률 68%, HP 95%, 적본진 미파괴 / Then 점수 = 2+2+2+0 = 6 → S등급, 자격 3계열 열림, 1개만 선택 가능
- Given 재도전 클리어 / Then 자본금이 정상 계산값의 50%로 지급된다

### FR-9. 공개 연출 `[P0]` ★ H2 검증 대상

**FR-9.1** 정산 직후, 점령 보상 선택 **전에** 실행한다 (감정의 절정을 보상 선택보다 앞에 둔다).
**FR-9.2 시퀀스** — 각 단계는 스킵 가능하나 기본은 자동 진행.

| 순서 | 연출 | 시간 |
|---|---|---|
| 1 | 플레이한 당일 차트가 축소되며 **전후 60거래일 일봉 차트** 안의 위치로 줌아웃 | 1.5s |
| 2 | **종목명 + 날짜 타이핑 연출** — `2020년 3월 19일 (목) · 대한항공` | 1.5s |
| 3 | 그날 실제 뉴스 헤드라인 **최대 3건** (자체 재작성 문구, 출처 링크) | 2.0s |
| 4 | 내 매매 전체가 차트 위에 표시 — **진입점 ▲/▼ 와 청산점을 선으로 연결**하고 이익 구간은 초록, 손실 구간은 빨강, 강제 청산은 ✕로 표기 `[v1.2]` | 1.5s |
| 5 | OHLCV 요약 + `당신은 N번 중 M번 적중. 이날 실제 종가는 −8.1%였습니다.` | 2.0s |
| 6 | `[차트 도감에 등록되었습니다]` 카드 획득 연출 | 1.5s |

**FR-9.3** 공개 정보는 정산 완료 후 **별도 API**로 받아온다 (FR-4.4 준수).
**FR-9.4** 스킵 버튼은 3초 후 노출한다 (첫 회차는 스킵 불가).
**FR-9.5** 패배 시에도 공개 연출을 실행하되 4·5단계 문구를 패배 맥락으로 바꾼다.
**FR-9.6** 공개 화면에서 **공유용 이미지 생성** 버튼을 제공한다 `[P1]`.

**수용 기준**
- Given 스테이지 클리어 / When 정산 화면에서 다음으로 진행 / Then 6단계 연출이 순서대로 실행되고 총 10초 내에 완료된다
- Given 첫 회차 플레이 / Then 스킵 버튼이 표시되지 않는다

### FR-10. 차트 도감 `[P1]`

**FR-10.1** 클리어(패배 제외)한 `종목×날짜` 조합이 카드로 영구 등록된다.
**FR-10.2 카드 표기**: 티커(텍스트), 날짜, 섹터, 당일 등락률, **내 적중률, 클리어 등급, 등급 희귀도**

|---|---|

| 영웅 | ±5% 초과 ~ ±10% |
| 전설 | ±10% 초과 **또는** 사전 지정된 역사적 날짜 |

**FR-10.4** 도감 목록은 섹터·희귀도·날짜로 필터·정렬 가능.
**FR-10.5** 로고·상표 이미지를 사용하지 않고 **티커 텍스트와 섹터 색상**으로만 카드를 구성한다 (§13).
**FR-10.6** MVP에서는 도감 완성도가 게임 스탯에 영향을 주지 않는다 (열람 전용).

### FR-11. 회사 & 부서 업그레이드 `[P0]`

**FR-11.1** 회사 화면(홈)에 표시: 자본금, 회사 등급, 부서 목록, 현재 AUM, 현재 운영비, 경계도.
**FR-11.2 MVP 부서 5종**

| # | 부서 | 효과 | Lv1 | Lv2 | Lv3 |
|---|---|---|---|---|---|
| 1 | 트레이딩 데스크 | 초기 AUM | 2000 (기본) | 2400 / 1,200 자본금 | 2800 / 3,000 |
| 2 | R&D | 타워 기본 피해 | +0% | +8% / 800 | +16% / 2,000 |
| 3 | 인사팀 | 유닛 HP | +0% | +10% / 800 | +20% / 2,000 |

| 5 | IR팀 | 정산 보너스 배수 | +0% | +5% / 1,000 | +10% / 2,500 |

> ✅ **v1.2 — 법무팀 효과 확정 (O-8 CLOSED).** v1.1에서 `LOSS_RATE`(L) 폐지로 효과가
> 소멸했던 법무팀에 **강제 청산선 완화**를 배정했다. Lv3이면 `r ≤ −1.30`까지 버틸 수 있으므로
> **일시적 역방향 움직임을 견디고 회복을 기다리는 플레이**가 가능해진다.
> 원래 법무팀이 담당하던 역할(=실패의 치명도 완화)과 감정적으로 동일하며,
> "법무팀이 막아줘서 강제 청산을 면했다"는 서사가 자연스럽게 붙는다.
>
> ⚠️ **밸런싱 주의**: 청산선 완화는 **손실 상한을 키우는 양날의 검**이다. Lv3에서 최대 손실은
> 여전히 stake 전액(FR-5.6)이지만 **청산까지 버티는 시간이 길어져 AUM 회전율이 떨어진다.**
> 봇 시뮬레이터에서 Lv3이 Lv1보다 실제로 유리한지 반드시 검증할 것 — 불리하게 나오면
> **돈 주고 사면 손해인 부서**가 되어 v1.1의 빈 껍데기 문제가 형태만 바꿔 재발한다. §16 O-11 참조.

**FR-11.3** 모든 업그레이드 효과는 **합연산**이다. 곱연산 금지.
**FR-11.4** 자본금이 부족하면 버튼이 비활성이고 부족액을 표시한다.
**FR-11.5** 업그레이드는 되돌릴 수 없다 (환불 없음).

**수용 기준**
- Given 트레이딩 데스크 Lv2 / When R3 진입 / Then 초기 AUM 2400
- Given 법무팀 Lv2 / When 포지션 보유 중 수익배율 `r`이 −1.10에 도달 / Then 강제 청산이 발동하지 **않는다** (적용 청산선 −1.15)
- Given 법무팀 Lv3 / When `r`이 −1.30에 도달 / Then 강제 청산이 발동하고 `pnl` = −stake로 확정된다

## 6. 데이터 모델

### 6.1 서버 DB (PostgreSQL)

```sql
-- 계정
CREATE TABLE accounts (
  id              UUID PRIMARY KEY,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_seen_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  capital         BIGINT      NOT NULL DEFAULT 0,   -- 자본금
  company_rank    SMALLINT    NOT NULL DEFAULT 1
);

-- 부서 레벨
CREATE TABLE departments (
  account_id      UUID REFERENCES accounts(id),
  dept_key        TEXT    NOT NULL,   -- trading_desk | rnd | hr | legal | ir
  level           SMALLINT NOT NULL DEFAULT 1,
  PRIMARY KEY (account_id, dept_key)
);

-- 지역 점령 상태
CREATE TABLE territories (
  account_id      UUID REFERENCES accounts(id),
  region_id       TEXT    NOT NULL,        -- R1 | R2 | R3
  captured_at     TIMESTAMPTZ,
  rewards_taken   TEXT[]  NOT NULL DEFAULT '{}',  -- finance | info | defense | offense
  best_grade      TEXT,                            -- S|A|B|C
  play_count      INT     NOT NULL DEFAULT 0,
  PRIMARY KEY (account_id, region_id)
);

-- 차트 원본 조합 (마스터 데이터, 계정 무관)
CREATE TABLE chart_sets (
  id              UUID PRIMARY KEY,       -- 불투명 ID. 클라이언트에 노출되는 유일한 식별자
  ticker          TEXT   NOT NULL,
  company_name    TEXT   NOT NULL,
  trade_date      DATE   NOT NULL,
  market          TEXT   NOT NULL,        -- KRX | NASDAQ ...
  sector          TEXT   NOT NULL,
  cap_tier        TEXT   NOT NULL,        -- large | mid | small
  region_id       TEXT   NOT NULL,        -- 어느 지역 풀에 속하는지
  archetype       TEXT   NOT NULL,        -- surge | plunge | range | reversal | earnings | panic
  day_change_pct  NUMERIC(6,3) NOT NULL,
  rarity          TEXT   NOT NULL,        -- common | rare | epic | legendary
  difficulty      SMALLINT NOT NULL,      -- 1~3 (시뮬레이션 검증 결과)
  bars_url        TEXT   NOT NULL,        -- 정적 파일 경로 (불투명)
  sigma_15m       NUMERIC(8,5) NOT NULL,
  sigma_30m       NUMERIC(8,5) NOT NULL,
  sigma_60m       NUMERIC(8,5) NOT NULL,
  events          JSONB  NOT NULL,        -- 사전 계산된 시장 이벤트
  news            JSONB  NOT NULL,        -- 재작성된 헤드라인 (공개 화면용)
  ohlcv_day       JSONB  NOT NULL,        -- 당일 요약 + 전후 60일 일봉
  UNIQUE (ticker, trade_date)
);
CREATE INDEX ON chart_sets (region_id, difficulty);

-- 스테이지 세션 (권위 있는 진행 상태)
CREATE TABLE stage_sessions (
  id              UUID PRIMARY KEY,
  account_id      UUID REFERENCES accounts(id),
  region_id       TEXT   NOT NULL,
  chart_set_id    UUID REFERENCES chart_sets(id),
  is_retry        BOOLEAN NOT NULL,
  started_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  ended_at        TIMESTAMPTZ,
  status          TEXT   NOT NULL,        -- active | cleared | failed | abandoned
  speed           NUMERIC(3,1) NOT NULL DEFAULT 1.0,
  -- 진입 시점에 확정된 파라미터 스냅샷 (중간에 부서 업글해도 영향 없게)
  params          JSONB  NOT NULL,        -- {aum, startingGold, aumDropPerWave, baseIncome, heat, towerSlots, ...}
                                          -- v1.1: lossRate 제거, startingGold·aumDropPerWave 추가
                                          -- v1.2: drawBand 제거, feeRate·liquidationLine·zMax·minHoldSec 추가
  -- 결과
  gold_earned     INT, gold_left INT, aum_left INT,
  hp_left         SMALLINT,
  -- v1.2: draws 폐지 (무승부 판정 소멸). 진입/청산 축으로 교체
  opens           SMALLINT, wins SMALLINT, losses SMALLINT, liquidations SMALLINT,
  enemy_base_destroyed BOOLEAN,
  grade           TEXT, capital_awarded BIGINT
);

-- 포지션 (판정 감사 로그) — v1.2 자유 매매제 반영
CREATE TABLE positions (
  id              BIGSERIAL PRIMARY KEY,
  session_id      UUID REFERENCES stage_sessions(id),
  seq             SMALLINT NOT NULL,      -- 세션 내 진입 순번 (최대 24)
  direction       TEXT   NOT NULL,        -- long | short
  stake           INT    NOT NULL,        -- 수수료 차감 전 투입액
  fee             INT    NOT NULL,        -- v1.2: stake × FEE_RATE (진입 시 확정)
  -- 진입
  open_at_ms      INT    NOT NULL,        -- v1.2: 세션 시작 기준 재생 경과 ms (서버 계산)
  open_price      NUMERIC(14,4) NOT NULL,
  -- 청산 (미청산 세션 종료 시 NULL 아님 — FR-8.1 강제 청산 처리)
  close_at_ms     INT,
  close_price     NUMERIC(14,4),
  delta_pct       NUMERIC(8,4),
  z_score         NUMERIC(6,3),           -- v1.2: 부호 있음 (음수 가능)
  r_multiplier    NUMERIC(6,3),           -- v1.2: B × clamp(z, ±Z_MAX)
  pnl             INT,                    -- v1.2: 순손익 (음수 가능). v1.3 골드 입금액 = floor(max(stake + pnl, 0) × GOLD_CONVERSION)
  close_reason    TEXT,                   -- v1.2: manual | liquidated | stage_end
  liq_line        NUMERIC(4,2) NOT NULL,  -- v1.2: 진입 시점 적용 청산선 (법무팀 레벨 반영 스냅샷)
  resolved_at     TIMESTAMPTZ
);

-- 도감
CREATE TABLE codex_entries (
  account_id      UUID REFERENCES accounts(id),
  chart_set_id    UUID REFERENCES chart_sets(id),
  first_cleared_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  best_accuracy   NUMERIC(5,4),
  best_grade      TEXT,

);

```

    │                           │ openBarIdx = i + 1
    │                           │ basePrice  = bars[i+1].close

    │                           │ AUM 차감, DB insert
    │◀── position.opened ───────│
    │                           │ (closeBarIdx 도달까지 대기)

> **v1.2 — 수수료를 진입 시 1회만 받는 이유.**
> 왕복(진입+청산) 부과가 현실적이지만, 이번 개정으로 손익분기 승률이 이미 크게 올라간 상태다
> (v1.0 40.3~50.2% → v1.1 약 52.6% → v1.2 재산출 필요). 수수료를 왕복으로 걸면 **같은 방향으로
> 세 번째 압력**이 되어 클리어 불가능 구간으로 넘어갈 위험이 있다. 단방향 1%로 시작하고
> 봇 시뮬레이터 결과를 보고 조정한다.

**환율 검증** (40만 회 시뮬레이션, `B=0.90`)

> ⚠️ **v1.1·v1.2 경제 변경으로 재산출 필요. 아래 표는 전부 무효다.**
> 이 표는 `LOSE payout = stake × (1 − L)` + 만기제 이산 판정 전제로 계산된 v1.0 수치다.
> **v1.2에서 손익 구조 자체가 이산 → 연속으로 바뀌었으므로 "승률"이라는 축이 더 이상 성립하지 않는다.**
>
> 재산출 시 축을 다음으로 교체할 것:
> - **행 축**: 예측 승률(p) → **평균 청산 z (`E[z]`)** — 플레이어가 평균적으로 몇 σ를 먹고 나오는가
> - **손익분기 조건**: `B × E[z] > FEE_RATE` → `E[z] > 0.0111` (B=0.90, FEE_RATE=0.01 기준)
> - **강제 청산 반영**: `r`의 하단이 −`LIQUIDATION_LINE`에서 잘리므로 손익 분포는 **좌측 절단**된다.
>   단순 기대값 계산이 성립하지 않으며 **몬테카를로가 필수**다
> - **새 변수**: 평균 보유 시간 — 자유 매매제에서는 회전율이 총 수익을 좌우한다
>
> 봇 시뮬레이터(§10 ⑥, W4)로 재측정하기 전까지 이 표를 밸런스 근거로 쓰지 말 것.

| 45% | 1.06 | 0.99 | 0.92 |
| 50% | 1.12 | 1.06 | 1.00 |
| 55% | 1.18 | 1.12 | 1.07 |
| 60% | 1.24 | 1.19 | 1.14 |
| 65% | 1.30 | 1.26 | 1.21 |
| **손익분기 승률** | **40.3%** | **45.6%** | **50.2%** |

### 9.3 지역별 설계 목표치 및 검증 결과 `[v1.3 전면 재산출]`

**총골드 모델**

```
총골드 = STARTING_GOLD + 기본수입 총액 + S × (1 + ρ) × GOLD_CONVERSION
  S = 시작 AUM + AUM_DROP_PER_WAVE × 13      (재순환 없음. §9.2 참고)
  ρ = 세션 전체 매매 수익률 (청산 pnl 합 / 총 투입액)
```

`startingAum`은 이 식에서 **역산된 값**이다 — 목표 ρ에서 총골드가 필요지출에 정확히 닿도록
`S = (필요지출 − 시작골드 − 기본수입) / ((1 + ρ) × GOLD_CONVERSION)`을 풀고 드롭 총액을 뺐다.

| 지역 | 난이도 | 점령수 | 시작골드 | 기본수입 | 시작 AUM | S | heat | 목표 ρ | 필요지출 |
|---|---|---|---|---|---|---|---|---|---|
| R1 여의도 | ★1 | 0 | 120 | 195 | **2,000** | **3,950** | 1.00 | +20% | 2,700 |
| R2 판교 | ★2 | 1 | 120 | 170 | **4,050** | **6,000** | 1.02 | +30% | 4,200 |
| R3 울산 | ★3 | 2 | 120 | 145 | **6,900** | **8,850** | 1.04 | +45% | 6,700 |

**검산표 — 총골드 대 필요지출**

| 지역 | 매매 미실행 | 세탁 (ρ=−1%) | 목표−5%p | **목표 ρ** | 목표+5%p | 필요지출 |
|---|---|---|---|---|---|---|
| **R1** | 315 (12%) | 2,270 (84%) | 2,586 (96%) | **2,685 (99.4%)** | 2,784 (103%) | 2,700 |
| **R2** | 290 (7%) | 3,260 (78%) | 4,040 (96%) | **4,190 (99.8%)** | 4,340 (103%) | 4,200 |
| **R3** | 265 (4%) | 4,646 (69%) | 6,460 (96%) | **6,681 (99.7%)** | 6,903 (103%) | 6,700 |

**설계 보증 4가지**
- **매매를 아예 안 하면 클리어 불가**: 총 자금이 265~315 G(기본 포탑 2기)뿐이다. 어떤 조합으로도
  13웨이브를 막지 못한다는 것은 실제 전투 시뮬레이션으로 고정돼 있다(`combat/economy-floor.test.ts`).
- **세탁이 최적해가 아니다**: z≈0 왕복만 반복하면 필요지출의 69~84%에 그친다. 원금이 돌아오지
  않으므로 반복 자체가 불가능하고, 받은 AUM을 전부 태워도 이 상한을 넘지 못한다.
- **AUM은 매매로 늘지 않는다**: 유입은 드롭뿐이므로 S가 위 표의 값으로 확정된다.
- **목표 ρ에서 통과 / −5%p에서 미달**: 세 지역 모두 목표에서 필요지출의 99% 이상, −5%p에서
  96%대로 미달한다.

> ⚠️ **게이트 대역이 v1.2보다 좁아졌다 — 알고 선택한 결과다.**
> 원금-이익 분리 시절 총골드는 `C + S × ρ`라 ρ가 유일한 항이었고 5%p 변화가 총골드를 20% 넘게
> 흔들었다. v1.3에서는 원금까지 골드가 되므로 ρ가 **1 위에 얹히는 항**이 되어
> `격차/필요지출 = 0.05 × (1 − C/필요지출) / (1 + ρ)` = 3.3~3.7%로 압축된다.
> 이 값은 `GOLD_CONVERSION`이나 S를 어떻게 잡아도 변하지 않는 **구조적 상수**다(둘 다 약분된다).
> 게이트의 실질은 "목표에서 반드시 미달"이며, 더 날카로운 대역이 필요하면 정산식의 형태 자체를
> (예: 이익분에만 별도 배수) 바꿔야 한다 — 그건 "투자 결과는 전부 골드"라는 이번 결정과 충돌한다.

> **밸런싱 목표 (사용자 확정, 2026-07-31)**: 숙련 플레이어 기준 **런 전체 수익률 +10~20%** 지점에서
> 클리어가 성립해야 한다. ⚠️ 이 목표는 **판당이 아니라 런 전체 기준**으로 해석한다 —
> 판당 +10~20%를 요구하면 필요 승률이 58~64%로 올라가 블라인드 차트에서 도달 불가능해진다.
> R1의 +20%는 이 범위 상단이고, R2·R3는 난이도 레버로 그 위에 얹은 값이다(R3 리스크는
> `combat/stages.ts` R3 주석 참고).

> ⚠️ **남은 검증**: 위 표는 "ρ를 달성했다면 클리어한다"는 **자원 회계**이며, 블라인드 차트에서
> ρ를 실제로 달성 가능한지는 별개 문제다. 필요 정확도(R1 약 61% / R2 67% / R3 75%)의 실증은
> 봇 시뮬레이터(§10 ⑥, W4) 몫으로 남아 있다.

④ 이벤트   패닉셀·FOMO 발동 시점 사전 계산 (최대 4개로 축약)
