## 1. 개요

### 1.1 제품 한 줄 정의

**정체를 가린 실제 과거 거래일 차트를 읽어 전쟁 자금을 만들고, 그 돈으로 일자형 타워디펜스 웨이브를 막아 지역을 점령하고, 클리어 후 그것이 어떤 회사의 어느 날이었는지 알게 되는 게임.**

### 1.2 MVP의 목적

MVP는 **기능을 많이 만드는 것이 목적이 아니라, 아래 두 가설을 검증하는 도구**다.

| 가설 | 검증 방법 | 통과 기준 |
|---|---|---|
| **H1 — 자금 도착의 쾌감**: 웨이브가 밀려오는 중에 예측이 적중해 골드가 꽂히고, 그 돈으로 급히 타워를 세우는 순간이 재미있다 | 플레이테스트 20명, 세션 후 설문 + 관찰 | "이 순간이 가장 재미있었다" 응답 ≥ 50% |
| **H2 — 공개의 쾌감**: 클리어 후 "이게 그 회사 그 날이었어?"라는 반응이 나온다 | 플레이테스트 관찰 (공개 화면에서의 발화·표정) | 소리 내어 반응한 인원 ≥ 60%, 공개 화면 평균 체류 ≥ 20초 |

### 1.3 성공 기준 (정량)

| 지표 | 목표 |
|---|---|
| 튜토리얼 완주율 | ≥ 70% |
| 첫 세션 평균 플레이 시간 | ≥ 15분 |
| 3지역 전체 클리어 도달률 | ≥ 40% |
| D1 재방문율 (테스터 기준) | ≥ 35% |
| 세션당 평균 포지션 수 | ≥ 8개 (예측을 실제로 쓰는지) |
| 공개 화면 스킵률 | ≤ 25% |

### 1.4 킬 크라이테리아 (이 경우 기획을 되돌린다)

- H1·H2 **둘 다** 통과 기준 미달
- 세션당 평균 포지션 수 < 4개 (예측이 무시되고 있음 = 코어 설계 실패)
- 테스터의 50% 이상이 "차트를 볼 시간이 없다"고 응답 (리듬 설계 실패 → 준비 페이즈 재설계 필요)

### 1.5 비목표 (Non-goals)

- 실제 투자 교육 도구가 되는 것 (부수 효과일 뿐, 목표 아님)
- 실시간 시세 반영 (MVP 범위 밖)
- 수익화 검증 (MVP는 결제 없음)
- 멀티플레이

## 2. 타겟 유저

| 페르소나 | 설명 | MVP에서의 니즈 |
|---|---|---|
| **P1 · 타워디펜스 팬 (주 타겟)** | Age of War·Bloons 계열을 즐긴 20~30대. 주식은 잘 모름 | 예측이 어렵지 않게 느껴져야 함 → 튜토리얼과 R1 난이도가 결정적 |
| **P2 · 주식·코인 관심층** | 차트를 볼 줄 알고 종목을 아는 20~40대 | 차트가 진짜 데이터라는 신뢰, 공개 화면의 정보 밀도 |
| **P3 · 수집형 플레이어** | 도감·컬렉션에 반응 | 차트 도감, 전설 등급 |

**MVP는 P1을 1순위로 잡는다.** P1이 예측 앞에서 좌절하면 아무것도 검증되지 않는다.

04:00  세계지도 등장 → 여의도(R1)만 활성, 나머지 잠김

10:40  정산 → 클리어 등급 → 공개 연출 → 도감 등록

## 5. 기능 요구사항

표기: `[P0]` 필수 / `[P1]` 있으면 좋음 / 수용 기준은 Given-When-Then.

---

### FR-1. 계정 & 저장 `[P1]`

**FR-1.1** 최초 접속 시 로그인 없이 **익명 계정(UUID)** 을 자동 발급하고 localStorage에 토큰을 저장한다.
**FR-1.2** 모든 진행도(자본금, 점령 지역, 부서 레벨, 도감)는 **서버에 저장**한다. 클라이언트 저장은 캐시일 뿐 권위가 없다.
**FR-1.3** 진행도 저장은 다음 시점에 발생: 스테이지 정산 완료, 점령 보상 선택, 부서 업그레이드.
**FR-1.4** 토큰 유실 시 진행도 복구는 지원하지 않는다 (MVP 한정, 화면에 명시).

**수용 기준**
- Given 최초 방문자 / When 페이지 진입 / Then 로그인 UI 없이 즉시 인트로가 시작되고 서버에 계정 1건이 생성된다
- Given 정산 완료 / When 브라우저를 새로고침 / Then 자본금·점령 상태가 유지된다

---

### FR-2. 세계지도 & 지역 선택 `[P0]`

**FR-2.1** MVP 지도는 **대한민국 3지역**만 표시한다.

| ID | 지역 | 섹터 | 차트 풀 | 인접 |
|---|---|---|---|---|
| R1 | 여의도 | 금융 | 은행·증권·보험 | (시작점) |
| R2 | 판교 | IT·플랫폼 | 게임·인터넷·SW | R1 |
| R3 | 울산 | 중공업·에너지 | 조선·정유·자동차 | R2 |

**FR-2.2** 지역 상태는 `잠김 / 도전가능 / 점령` 3가지. **인접 지역을 점령해야 다음 지역이 `도전가능`** 이 된다.
**FR-2.3** 각 지역 노드에 표시: 지역명, 섹터, **난이도 등급(★1~3)**, 점령 여부, 획득한 점령 보상 계열 아이콘.
**FR-2.4** 점령한 지역도 재도전 가능. 재도전 시:
  - 같은 섹터의 **다른 종목×날짜 조합**이 배정된다 (재출현 쿨다운 §FR-3.6)
  - 자본금 정산은 **50%만** 지급 (파밍 방지)
  - 점령 보상은 **아직 획득하지 않은 계열만** 선택 가능
**FR-2.5** 지도 화면에 상시 표시: 자본금, 점령 지역 수, **현재 운영비**, **현재 경계도 계수**.

**수용 기준**
- Given R1 미점령 / When R2 노드 클릭 / Then "인접 지역을 먼저 점령하세요" 안내가 뜨고 진입 불가
- Given R1 점령 & 재무 계열 이미 획득 / When R1 재도전 클리어 / Then 재무 계열이 선택 목록에서 비활성 표시된다

### FR-3. 차트 리플레이 엔진 `[P0]` ★ 코어

**FR-3.1 시간 매핑**

```
1 게임초 = 1 실거래분
1 스테이지 = 실제 1거래일 = 390분 = 390초 = 6분 30초
1 웨이브 = 30초 = 실제 30분봉 1개 → 총 13웨이브
웨이브 사이클 = 준비 10초 + 웨이브 진행 20초
차트는 준비 페이즈에도 계속 흐른다 (일시정지 없음)
```

**FR-3.2** 스테이지 데이터는 **1분봉 OHLCV 390개**로 구성된 정적 파일이며, 스테이지 시작 시 **전량 프리로드**한다 (스트리밍 안 함).
**FR-3.3** 화면 렌더는 1분봉 사이를 **선형 보간**해 초당 60프레임으로 부드럽게 그린다. 보간은 **표현 전용**이다.
**FR-3.4** 예측 판정은 **반드시 실제 1분봉 종가**를 사용한다. 보간값으로 판정하면 안 된다. (판정은 서버가 수행 — FR-5)
**FR-3.5** 배속 옵션 `0.5x / 1x / 2x`. 배속 변경은 **스테이지 시작 전에만** 가능하고 진행 중 변경 불가 (판정 일관성).
**FR-3.6 조합 쿨다운**: 한 번 플레이한 `종목×날짜` 조합은 해당 계정에서 **20회 플레이 동안 재출현하지 않는다.**
**FR-3.7 진행 표시**: 상단에 `09:00 ─●────── 15:30` 시각 진행 바. **시각은 보여주고 날짜는 숨긴다.**

**수용 기준**
- Given 1x 배속 / When 스테이지 시작부터 종료까지 / Then 총 경과 시간이 390초 ± 2초다
- Given 30초 만기 포지션 / When 판정 발생 / Then 서버 로그의 판정 가격이 해당 1분봉의 실제 종가와 정확히 일치한다
- Given 동일 계정으로 R1을 3회 플레이 / Then 세 번 모두 다른 종목×날짜 조합이 배정된다

### FR-4. 블라인드 규칙 `[P0]` ★ 코어

**FR-4.1 은닉 항목** — 플레이 중 다음을 절대 노출하지 않는다.

| 항목 | 처리 |
|---|---|
| 종목명·티커·로고 | 완전 미표시 |
| 날짜·연도·요일 | 완전 미표시 (시각만 표시) |
| 가격 절대값 | Y축은 **당일 시가 = 0%** 기준 백분율만 |
| 거래량 절대값 | 20일 평균 대비 **배수**로만 표시 (`2.4×`) |

**FR-4.2 노출 항목** — 익명 태그만 제공: `아시아 · 금융 · 대형주` (지역·섹터·시가총액 규모 3종)
**FR-4.3** 데이터 변형(좌우 반전, 가격 스케일 조작, 합성 데이터 혼입)을 **금지**한다. 진짜 데이터라는 사실이 제품의 핵심 가치다.
**FR-4.4** 클라이언트에 전달되는 스테이지 데이터 페이로드에 **종목명·날짜 필드를 포함하지 않는다.** (개발자 도구로도 알아낼 수 없어야 함) 공개용 정보는 정산 후 별도 API로 받는다.
**FR-4.5** 스테이지 데이터 파일명·URL에도 종목·날짜가 유추 가능한 문자열을 쓰지 않는다 → **불투명 ID(UUID)** 사용.

**수용 기준**
- Given 스테이지 진행 중 / When 브라우저 개발자 도구로 네트워크 응답과 메모리를 검사 / Then 종목명과 날짜를 얻을 수 없다
- Given 스테이지 데이터 URL / Then URL에 티커·날짜 문자열이 없다

### FR-5. 포지션 시스템 `[P0]` ★ 코어

**FR-5.1 UI 구성** — 차트 패널 하단에 고정.
```
[ LONG ▲ ]  [ SHORT ▼ ]
투입:  10%   25%   50%   ALL
만기:  15초(15분봉)   30초(30분봉)
```
**FR-5.2** 동시 보유 포지션은 **1개**로 제한한다 (MVP). 보유 중에는 신규 오픈 버튼이 비활성.
**FR-5.3** 스테이지당 최대 포지션 수 **24개**.
**FR-5.4 기준가 결정**: 서버가 오픈 요청을 받은 시각 이후 **다음 1분봉의 종가**를 기준가로 스냅샷한다. 요청 시점의 보간 가격을 쓰지 않는다.
**FR-5.5 만기 판정 수식**

```
Δ%  = (만기가 − 기준가) / 기준가 × 100
σ   = 해당 조합·해당 만기 구간의 사전 계산된 수익률 표준편차 (스테이지 데이터에 포함)
z   = |Δ%| / σ
M   = clamp(z, 0.5, 3.0)

z < 0.25            → DRAW   : payout = stake × 1.0        # 원금 반환
방향 적중            → WIN    : payout = stake × (1 + B × M)
방향 실패            → LOSE   : payout = 0                  # v1.1 — stake 전액 소실

B (배당 계수) = 0.90  — 전 지역 고정
```

> **v1.1 변경**: LOSE의 payout이 `stake × (1 − L)`에서 **0**으로 바뀌었다.
> 즉 **AUM은 예측에 성공했을 때만 골드로 전환된다** (DRAW는 원금 반환이므로 손익 0).
> 이에 따라 **`LOSS_RATE`(L) 상수는 폐지**되었다.
> ⚠️ **L은 유일한 지역 난이도 차등 레버였다** (§9.1). L이 사라지면서 R1/R2/R3의
> 예측 난이도는 **완전히 평평해진다.** 이는 인지된 상태에서 수용된 결정이다 —
> AUM이 전투 중 재생되는 자원(FR-6.8-a)이 되어 단일 실패의 치명도가 낮아졌기 때문이다.
> 다만 **지역 난이도 차등 레버는 별도 재설계가 필요하다** (heat 계수·웨이브 테이블·
> `AUM_DROP_PER_WAVE`의 지역별 차등 등이 후보). §16 오픈 이슈 O-7 참조.

**FR-5.6** `payout`은 **골드로 즉시 입금**되고, 투입한 `stake`는 AUM에서 즉시 차감된다.
LOSE 시에는 입금이 발생하지 않으며 차감된 `stake`는 회수되지 않는다.
**FR-5.7** AUM은 **포지션 투입 외의 용도로 사용할 수 없다.** 골드로 직접 전환하는 기능은
존재하지 않으며, 골드로의 유일한 전환 경로는 **예측 성공(WIN)** 이다.
AUM의 획득 경로는 **① 스테이지 시작 시 지급**(부서 레벨 기준)과
**② 적 처치 드롭**(FR-6.8-a) 두 가지다.
**FR-5.8** 포지션 진행 중 차트 위에 **진입 지점 마커와 만기까지 남은 시간**을 표시한다.
**FR-5.9** 만기 도달 시 결과 연출: WIN 초록 팝업 + 금액, LOSE 빨강, DRAW 회색. **연출은 0.8초 이내**로 짧게 (전투 흐름을 끊지 않아야 함).
**FR-5.10** 초당 최대 1건의 오픈 요청만 허용한다 (봇 방지).

**수용 기준**
- Given AUM 2000, 25% 투입, WIN, M=1.0 / Then 골드 증가분 = 500 × (1+0.9×1.0) = 950, AUM = 1500
- Given AUM 2000, 25% 투입, LOSE / Then 골드 증가분 = 0, AUM = 1500 (stake 500 전액 소실)
- Given AUM 2000, 25% 투입, DRAW / Then 골드 증가분 = 500 (원금 반환), AUM = 1500 — 순손익 0
- Given 포지션 보유 중 / When LONG 버튼 클릭 / Then 버튼이 비활성이고 아무 일도 일어나지 않는다
- Given 클라이언트가 조작된 판정 결과를 전송 / Then 서버가 무시하고 서버 판정값을 권위로 사용한다

```
┌──────────────────────────────────────────────────────────┐
│ [아시아 · 금융 · 대형주]   09:00 ──●──── 15:30            │  ← 블라인드 태그 + 진행바
│  ╭─ 차트 (당일 시가 0% 기준) ───────────────────╮ 거래량 2.4× │
│  ╰──────────────────────────────────────────────╯          │
│  [LONG ▲][SHORT ▼]  10% 25% 50% ALL   15s 30s              │
├──────────────────────────────────────────────────────────┤
│ HP ████████░░ 82   골드 1,240   AUM 1,500   W 4/13  ⏱ 00:14│
├──────────────────────────────────────────────────────────┤
│                  ✈    ✈       ✈          ← 공중 레인       │
│ ▓▓▓                                            ▓▓▓        │

**FR-6.2 레인**: 지상 1레인 + 공중 1레인. 지상 유닛은 지상만, 공중 적은 대공 가능 타워만 공격 가능.
**FR-6.3 타워 슬롯**: 아군 진영 앞 고정 **6칸**. MVP에서 슬롯 확장은 방어 계열 점령 보상으로 최대 8칸.

**FR-6.4 타워 3종**

| 타워 | 건설 | 업그레이드 | 대상 | 특성 |
|---|---|---|---|---|
| 기본 포탑 | 120 G | 180 G | 지상 | 단일 표적, 중간 DPS |
| 대공 포대 | 120 G | 180 G | 공중 | 공중 전용, 고 DPS |
| 광역 포탑 | 160 G | 220 G | 지상 | 범위 피해, 낮은 DPS |

**FR-6.5 유닛 3종** (소환 후 자동 우측 전진, 라인 교전)

| 유닛 | 비용 | HP | DPS | 역할 |
|---|---|---|---|---|
| 인턴 | 30 G | 낮음 | 낮음 | 물량·시간 벌기 |
| 애널리스트 | 60 G | 중간 | 중간 | 표준 |
| 트레이더 | 90 G | 높음 | 높음 | 주력 |

**FR-6.6 스킬 1종**: `공시 폭탄` — 200 G, 화면 전체 지상 적에게 즉시 피해, 쿨다운 45초.

**FR-6.7 웨이브 구성**: 13웨이브. 웨이브 `w`의 적 스펙:
```
적 수    = ceil(baseCount[w] × heat)
적 HP    = baseHP[w] × heat
적 이동속도 = baseSpeed[w]
heat (경계도 계수) = 1 + (점령 지역 수 × 0.02)
```
`baseCount` / `baseHP` / `baseSpeed`는 지역별 데이터 테이블로 관리한다 (§9.3).

**FR-6.8 기본 수입**: 각 웨이브 시작 시 골드 지급.
```
총 기본 수입 = 25 × 13 − (점령 지역 수 × 25)        ← 이것이 권위 있는 값
웨이브당 지급 = floor(총 기본 수입 / 13)
마지막 웨이브(13) = 총 기본 수입 − (웨이브당 지급 × 12)   ← 나머지 보정
```
> 반드시 총액을 먼저 확정하고 웨이브에 분배한다. 웨이브당 값을 먼저 내림 계산하면 총액이 §9.3 설계치와 어긋난다.
> 예) 점령 2개 → 총 275 G, 웨이브 1~12 각 21 G, 웨이브 13은 275 − 252 = 23 G

**FR-6.8-a AUM 드롭** `[v1.1 신규]`: **적 1체를 처치할 때마다 AUM을 획득**한다.

```
웨이브 w의 적 수  = ceil(baseCount[w] × heat)          ← FR-6.7과 동일한 값
개체당 AUM 드롭   = floor(AUM_DROP_PER_WAVE / 웨이브 w의 적 수)
```

- **웨이브당 AUM 드롭 총량을 상수로 먼저 고정하고, 그 웨이브의 적 개체 수로 나눠 분배한다.**
  개체당 고정 드롭으로 설계하면 후반 웨이브(적 수·heat 증가)에서 AUM이 폭증해
  환율 밸런스가 붕괴한다. 총량 고정이 이 설계의 핵심이다.
- **처치하지 못한 적의 몫은 지급하지 않는다.** 본진을 통과하거나 살아남은 적의
  드롭분은 소멸하므로, 웨이브를 **전멸**시켜야 해당 웨이브의 AUM을 전액 획득한다.
- 나눗셈은 **내림**이므로 개체당 드롭 × 적 수 ≤ `AUM_DROP_PER_WAVE`이다.
  나머지는 버린다(기본 수입 FR-6.8과 달리 나머지 보정을 하지 않는다).
  전멸시켜도 총량에 미달할 수 있으며 이는 의도된 동작이다.
- 적 수가 `AUM_DROP_PER_WAVE`를 초과하면 개체당 드롭이 0이 된다.
  §9.4 웨이브 테이블(최대 14체)과 초기값 150 기준으로는 발생하지 않으나,
  튜닝 시 이 하한을 확인해야 한다.
- 드롭된 AUM은 **즉시 AUM 잔액에 가산**되며 그 웨이브 중에도 포지션 투입에 쓸 수 있다.

> **설계 의도**: v1.0에서 AUM은 스테이지 시작 시 1회 지급되는 소모성 자원이었고,
> 연속 실패는 곧 회복 불가능한 자금 고갈이었다. v1.1에서 AUM을 **전투 성과로
> 재생되는 자원**으로 바꿔, LOSE payout=0(FR-5.5)의 가혹함을 상쇄하고
> "전투를 잘하면 예측 기회가 늘어난다"는 전투↔예측 되먹임 고리를 만든다.

**FR-6.8-b 초기 골드** `[v1.1 신규]`: 스테이지 시작 시 골드를 `STARTING_GOLD` 만큼 지급한다.

- v1.0에서는 골드 시작 지급이 없어 웨이브 1의 기본 수입(약 25 G)만으로 시작했고,
  가장 싼 타워(기본 포탑 120 G)조차 즉시 지을 수 없었다.
- `STARTING_GOLD = 200`은 **기본 포탑 1기(120 G) + 여유 80 G**를 의도한 값이다.
  **타워 최소 1기는 웨이브 1 이전에 반드시 건설 가능해야 한다**는 것이 이 상수의 제약이다.
- 초기 AUM 지급은 기존 로직(부서 트레이딩데스크 레벨 기준, §9.2 `AUM_BY_DESK_LV`)을 그대로 유지한다.
- `STARTING_GOLD`는 정산의 `총 획득 골드`(FR-8.1 잔여골드율 분모)에 포함된다.

**FR-6.9 패배 조건**: 본진 HP 0. 패배 시 정산 없음, 자본금 0, 도감 등록 없음. **단 공개 연출은 보여준다** (실패해도 정체는 알려줘야 재도전 동기가 생김).
**FR-6.10 승리 조건**: 13웨이브 방어 완료. 적 본진 파괴는 **선택적 보너스** — 유닛을 우측 끝까지 밀어 적 본진 HP를 0으로 만들면 `공격 계열` 자격이 열린다.
**FR-6.11 일시정지**: 불가. 단 `이탈` 가능하며 이탈 시 패배 처리.

**수용 기준**
- Given 점령 지역 2개 / When 스테이지 진입 / Then 총 기본 수입 = 325 − 50 = 275 G (웨이브 1~12 각 21 G, 웨이브 13 은 23 G), heat = 1.04
- Given 스테이지 진입 / Then 골드가 `STARTING_GOLD` = 200 으로 시작하며 기본 포탑(120 G) 1기를 즉시 건설할 수 있다
- Given `AUM_DROP_PER_WAVE`=150, 웨이브 1의 적 수 3체 / When 3체 전부 처치 / Then 개체당 50 AUM, 합계 150 AUM 획득
- Given `AUM_DROP_PER_WAVE`=150, 적 수 3체 / When 2체만 처치하고 1체를 놓침 / Then 100 AUM만 획득 (놓친 몫은 소멸)
- Given `AUM_DROP_PER_WAVE`=150, 웨이브 13의 적 수 14체 / When 14체 전부 처치 / Then 개체당 floor(150/14)=10 AUM, 합계 140 AUM (나머지 10은 버림, 보정 없음)
- Given 본진 HP 0 / Then 즉시 전투 종료 후 공개 연출 화면으로 이동하며 자본금 0이 표시된다

### FR-7. 시장 이벤트 `[P0]`

**FR-7.1** 리플레이 진행 중 실제 데이터가 조건을 만족하면 이벤트가 발동한다. 발동 시점은 **스테이지 데이터에 사전 계산되어 포함**된다 (런타임 판정 아님 → 연출 타이밍 정확도 확보).

| 이벤트 | 발동 조건 (실제 데이터) | 효과 | 지속 |
|---|---|---|---|
| **패닉 셀** | 직전 15분 수익률 ≤ −1.0σ | 다음 웨이브 적 수 +30%, 이동속도 +20% | 1웨이브 |
| **FOMO 랠리** | 직전 15분 수익률 ≥ +1.0σ | 아군 공격력 +25%, 적 HP +15% | 1웨이브 |

**FR-7.2** 발동 시 화면 상단에 **속보 배너**(2초) + 화면 색조 변화(패닉=적색, FOMO=녹색) + 진동/셰이크 연출.
**FR-7.3** 이벤트는 스테이지당 최대 4회로 제한한다 (연출 피로 방지). 초과 조건은 강도 순으로 상위 4개만 채택.
**FR-7.4** 두 이벤트가 같은 웨이브에 겹치면 나중 것이 앞의 것을 대체한다.

**수용 기준**
- Given 사전 계산된 이벤트 목록에 `t=210s 패닉셀` / When 리플레이가 210초에 도달 / Then 배너가 뜨고 다음 웨이브 적 수가 1.3배가 된다

### FR-8. 정산 & 점령 보상 `[P0]`

**FR-8.1 정산 수식**

```
잔여골드율 = 잔여 골드 / (총 획득 골드)
적중률    = WIN 수 / (WIN + LOSE 수)          # DRAW는 분모에서 제외

기본 자본금 = 잔여 골드 × 1.0 + 잔여 AUM × 0.5
보너스 배수 = 1.0
  + (본진 HP 100%       → +0.20)
  + (적중률 ≥ 0.60      → +0.15)
  + (적중률 ≥ 0.70      → +0.30, 위와 중복 아님 — 상위만 적용)
등급 배수  = S 1.6 / A 1.3 / B 1.1 / C 1.0

최종 자본금 = 기본 자본금 × 보너스 배수 × 등급 배수 × (재도전이면 0.5)
```

> ⚠️ **v1.1 영향 2건 — 수식은 그대로 두되 재검증 대상이다.**
> ① `총 획득 골드`(잔여골드율 분모)에 `STARTING_GOLD` 200 G가 새로 포함된다.
> ② `잔여 AUM × 0.5` 항이 **AUM 파밍 유인**을 만든다. AUM이 전투 드롭으로 재생되므로
> (FR-6.8-a) "예측을 아예 하지 않고 AUM을 쌓아 정산에서 0.5배로 환전"하는 전략이
> 성립할 수 있다. 이는 **"예측을 건너뛴 플레이는 존재할 수 없다"(§9.3)는 코어 설계
> 보증과 정면으로 충돌**하므로 봇 시뮬레이터로 우위 여부를 확인해야 한다.
> 성립할 경우 대응: 잔여 AUM 환산율 인하 / 잔여 AUM 환산에 상한 부여 /
> 최소 포지션 수 미달 시 환산 제외.

**FR-8.2 등급 산정** — 아래 점수 합으로 결정.

| 항목 | 점수 |
|---|---|
| 잔여골드율 ≥ 20% | 2점 / ≥ 10% 1점 |
| 적중률 ≥ 65% | 2점 / ≥ 55% 1점 |
| 본진 HP ≥ 90% | 2점 / ≥ 70% 1점 |
| 적 본진 파괴 | 1점 |

`S` 6점 이상 / `A` 4~5점 / `B` 2~3점 / `C` 0~1점

**FR-8.3 점령 보상 자격** — 아래 조건을 만족한 계열이 **선택 가능**해진다.

| 조건 | 계열 | MVP 보상 내용 |
|---|---|---|
| 잔여골드율 ≥ 20% | **재무** | 운영비 −10 G/지역 |
| 적중률 ≥ 65% | **정보** | 리서치 Lv1 해금 (거래량 30분봉 바 표시) |
| 본진 HP ≥ 90% | **방어** | 타워 슬롯 +1 |
| 적 본진 파괴 | **공격** | 유닛 소환 비용 −15% |

**FR-8.4** 자격이 여러 개 열려도 **1개만 선택**한다. 선택하지 않은 계열은 그 지역에서 **영구 포기**된다 (재도전으로만 재획득).
**FR-8.5** 자격이 하나도 없으면 기본 보상만(자본금 + 도감 등록) 지급하고 선택 UI를 건너뛴다.
**FR-8.6** 보상 선택 UI는 각 계열의 효과를 **정확한 수치로** 표시한다.

**수용 기준**
- Given 잔여골드율 25%, 적중률 68%, HP 95%, 적본진 미파괴 / Then 점수 = 2+2+2+0 = 6 → S등급, 자격 3계열 열림, 1개만 선택 가능
- Given 재도전 클리어 / Then 자본금이 정상 계산값의 50%로 지급된다

### FR-9. 공개 연출 `[P0]` ★ H2 검증 대상

**FR-9.1** 정산 직후, 점령 보상 선택 **전에** 실행한다 (감정의 절정을 보상 선택보다 앞에 둔다).
**FR-9.2 시퀀스** — 각 단계는 스킵 가능하나 기본은 자동 진행.

| 순서 | 연출 | 시간 |
|---|---|---|
| 1 | 플레이한 당일 차트가 축소되며 **전후 60거래일 일봉 차트** 안의 위치로 줌아웃 | 1.5s |
| 2 | **종목명 + 날짜 타이핑 연출** — `2020년 3월 19일 (목) · 대한항공` | 1.5s |
| 3 | 그날 실제 뉴스 헤드라인 **최대 3건** (자체 재작성 문구, 출처 링크) | 2.0s |
| 4 | 내가 걸었던 포지션 전체가 차트 위에 마커로 표시 (○ WIN / ✕ LOSE / − DRAW) | 1.5s |
| 5 | OHLCV 요약 + `당신은 N번 중 M번 적중. 이날 실제 종가는 −8.1%였습니다.` | 2.0s |
| 6 | `[차트 도감에 등록되었습니다]` 카드 획득 연출 | 1.5s |

**FR-9.3** 공개 정보는 정산 완료 후 **별도 API**로 받아온다 (FR-4.4 준수).
**FR-9.4** 스킵 버튼은 3초 후 노출한다 (첫 회차는 스킵 불가).
**FR-9.5** 패배 시에도 공개 연출을 실행하되 4·5단계 문구를 패배 맥락으로 바꾼다.
**FR-9.6** 공개 화면에서 **공유용 이미지 생성** 버튼을 제공한다 `[P1]`.

**수용 기준**
- Given 스테이지 클리어 / When 정산 화면에서 다음으로 진행 / Then 6단계 연출이 순서대로 실행되고 총 10초 내에 완료된다
- Given 첫 회차 플레이 / Then 스킵 버튼이 표시되지 않는다

### FR-10. 차트 도감 `[P1]`

**FR-10.1** 클리어(패배 제외)한 `종목×날짜` 조합이 카드로 영구 등록된다.
**FR-10.2 카드 표기**: 티커(텍스트), 날짜, 섹터, 당일 등락률, **내 적중률, 클리어 등급, 등급 희귀도**
**FR-10.3 희귀도**

| 등급 | 기준 (당일 종가 등락률) |
|---|---|
| 일반 | ±2% 이내 |
| 희귀 | ±2% 초과 ~ ±5% |
| 영웅 | ±5% 초과 ~ ±10% |
| 전설 | ±10% 초과 **또는** 사전 지정된 역사적 날짜 |

**FR-10.4** 도감 목록은 섹터·희귀도·날짜로 필터·정렬 가능.
**FR-10.5** 로고·상표 이미지를 사용하지 않고 **티커 텍스트와 섹터 색상**으로만 카드를 구성한다 (§13).
**FR-10.6** MVP에서는 도감 완성도가 게임 스탯에 영향을 주지 않는다 (열람 전용).

    "waveCount": 13,
    "waveTable": [ { "count": 4, "hp": 60, "speed": 1.0 }, … ]
  }
}
```
> `chartSetId`는 응답에 포함하지 않는다. 세션 ID로만 참조한다.
> **v1.1**: `lossRate` 필드는 **제거**되었다(L 폐지, FR-5.5).
> `startingGold` · `aumDropPerWave` 2개가 추가되었다.

### 7.2 WebSocket — 포지션 판정 전용

`wss://…/ws/stage?session={id}`

**클라이언트 → 서버**

```json
{ "op": "position.open", "seq": 5, "direction": "long", "stake": 600, "expirySec": 30 }
{ "op": "clock.sync",   "clientBarIdx": 142 }
```

**서버 → 클라이언트**

```json
{ "op": "position.opened",
  "seq": 5, "openBarIdx": 143, "closeBarIdx": 173, "basePrice": 14240 }

{ "op": "position.resolved",
  "seq": 5, "outcome": "win", "deltaPct": 0.83, "m": 1.41,
  "payout": 1361, "goldTotal": 2104, "aumLeft": 1800 }

{ "op": "error", "code": "POSITION_ALREADY_OPEN" | "RATE_LIMITED" | "MAX_POSITIONS" }
```

**에러 코드**: `POSITION_ALREADY_OPEN` / `RATE_LIMITED` / `MAX_POSITIONS` / `INSUFFICIENT_AUM` / `SESSION_ENDED` / `INVALID_SEQ`

### 7.3 판정 시퀀스

```
클라이언트                    서버
    │  position.open (seq=5) ──▶│
    │                           │ 현재 서버 기준 bar 인덱스 확인 (i)
    │                           │ openBarIdx = i + 1
    │                           │ basePrice  = bars[i+1].close
    │                           │ closeBarIdx = openBarIdx + expiry
    │                           │ AUM 차감, DB insert
    │◀── position.opened ───────│
    │                           │ (closeBarIdx 도달까지 대기)
    │                           │ Δ%, z, M 계산 → outcome 결정
    │                           │ payout 골드 입금, DB update
    │◀── position.resolved ─────│
```

**서버 기준 bar 인덱스**: 세션 `started_at`과 `speed`로 서버가 독립 계산한다. 클라이언트가 보낸 인덱스는 **검증용으로만** 쓰고, 서버값과 3 bar 이상 벌어지면 `clock.resync`를 보내 클라이언트를 서버에 맞춘다.

              ↓
④ 이벤트   패닉셀·FOMO 발동 시점 사전 계산 (최대 4개로 축약)
              ↓
⑤ 뉴스     그날 헤드라인 → 사실 추출 → 자체 문구로 재작성 (원문 복제 금지)

## 17. 용어집

| 용어 | 정의 |
|---|---|
| **AUM** | 운용자금. **예측 전용 재화이며 골드로 직접 전환할 수 없다.** 획득 경로 2가지 — ① 스테이지 진입 시 지급(부서 레벨 기준) ② **적 처치 시 드롭**(웨이브당 총량 고정 후 개체 분배, FR-6.8-a). 골드로 넘어가는 유일한 통로는 **예측 성공(WIN)** 이다 |
| **골드** | 전투 재화. 타워·유닛·스킬 구매에 사용. 획득 경로 3가지 — ① **스테이지 시작 시 초기 지급**(`STARTING_GOLD`) ② 웨이브별 기본 수입 ③ 포지션 청산(WIN 또는 DRAW). **LOSE는 골드를 만들지 않는다** |
| **자본금** | 메타 재화. 스테이지 정산으로 획득, 부서 업그레이드에 사용 |
| **포지션** | 예측 1건 (방향 + 투입액 + 만기) |
| **환율** | 투입 AUM 대비 회수 골드의 기대 배수. 예측 승률의 함수 |
| **경계도(heat)** | 점령 지역 수에 비례해 웨이브 강도를 올리는 계수 |
| **운영비** | 점령 지역 수에 비례해 기본 수입에서 차감되는 비용 |
| **아키타입** | 그 거래일의 성격 분류 (급등·급락·횡보·반전·실적·패닉) |
| **조합** | `종목 × 거래일` 1건. 스테이지 콘텐츠의 최소 단위 |
| **블라인드** | 플레이 중 종목·날짜·가격 절대값을 은닉하는 규칙 |
| **공개 연출** | 클리어 후 조합의 정체를 드러내는 시퀀스 |
