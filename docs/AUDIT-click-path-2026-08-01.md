## CLICK-PATH-001 · CRITICAL — 스테이지 종료 직전 무음 전체 리셋

**패턴**: 부작용 간섭

`STAGE_DURATION_MS = 390_000`(`market/types.ts:26`)과 전투 총시간 `13 × WAVE_DURATION_MS = 390_000`이 **정확히 같다.**

`render` 순서:
1. `stepCombatFrame`
2. `phase !== 'running'` 조기 반환
3. `state.finished` → 리셋

그런데 `cleared` 조건(`simulate.ts:209–217`)은 **웨이브 13 교전창 소진 + 생존 적 0**을 요구한다.
13웨이브는 25초 창에 14마리를 뿌리므로 **390초 시점에 반드시 생존자가 있다.**
게다가 전투 dt 는 `MAX_FRAME_DT_MS = 250`으로 잘리지만(`stage.ts:259`) 리플레이는 절대 벽시계라,
탭 전환·프레임 히치가 한 번이라도 있으면 전투가 더 뒤처진다.

| | |
|---|---|
| **예상** | "스테이지 클리어" 배너 |
| **실제** | `closeAtStageEnd` → `seed += 1` → `session = null` → 다음 프레임에 **골드 120 · 웨이브 0 · 타워 0 으로 무음 재시작**. 배너·로그·연출 전부 없음 |

**부수 피해**
- `closeAtStageEnd` 가 만든 `pendingNotice` 를 아무도 `takeNotice` 하지 않아 **골드 비행 연출이 사라진다**
- **정산 골드가 세션과 함께 폐기된다** (FR-8.1 정산이 셸에 아예 없다)

> **클리어 배너는 Space 로 준비 13회를 전부 건너뛴 경우에만 도달 가능**하다(65초 확보).
> 그런데 그 Space 가 CLICK-PATH-005 때문에 정상 동선에서 안 먹힌다.

**수정안**: `state.finished` 분기를 `phase === 'running'`일 때 리셋이 아니라 **전투 종료 대기(또는 배너 표시)**로 바꾸고, 리셋 전에 `takeNotice`·정산을 소비.

## CLICK-PATH-002 · HIGH — 배속 버튼이 진행 중 판을 지운다

**패턴**: 순차 되돌림 / 상태 전이 누락

```
speed = …; syncButtons(); session = null;
```

FR-3.5 는 "진행 중 안 바뀐다"인데 **버튼은 플레이 중에도 활성**이다.
웨이브 10에서 4x 를 누르면 지갑·타워·웨이브가 전부 사라지고 **화면엔 아무 안내가 없다.**
라벨("2x")이 약속하는 것과 최종 상태가 다르다.

**수정안**: 세션이 있으면 `disabled`, 또는 "새 스테이지로 다시 시작합니다" 명시.

## CLICK-PATH-003 · MEDIUM — 업그레이드 로그가 실패를 성공이라고 말한다

`stage.ts:449–452`. `current.upgrade(slot)` 은 `void` 이고 골드 부족 시 **조용히 실패**하는데
(`session.ts:190–197`), 로그는 **무조건** `"… 업그레이드 (60G)"` 를 찍는다.
스킬 쪽(`castSkill`)은 불리언을 확인하는데 여기만 안 한다.

**수정안**: `upgrade` 가 boolean 을 반환하도록 하고 성공 시에만 로그.

## CLICK-PATH-004 · MEDIUM — 유닛 소환 버튼 3종이 항상 활성

`roster-logic.ts` 가 `disabled` 를 전혀 내지 않고, 셸에도 유닛용 `sync*` 가 없다
(스킬은 `syncSkillButtons`, 타워 슬롯은 데칼로 처리).
골드 부족 시 클릭해도 **무반응·무메시지** — "눌리는데 아무 일도 없는 버튼".

## CLICK-PATH-005 · MEDIUM — Space 가 정상 동선에서 먹히지 않는다

`stage.ts:474–482` 가 포커스 대상이 버튼이면 반환한다.
**준비 5초는 정확히 빌드바 버튼을 누르는 구간**이라, 타워·스킬 버튼을 클릭한 직후
포커스가 그 버튼에 남아 Space 가 삼켜진다.
화면은 "Space 로 바로 시작"이라고 **계속 말한다**(`stage-dom.ts:90`).

**수정안**: 버튼 예외를 `document.activeElement` 가 아닌 실제 Space 활성화 대상으로 좁히거나,
카운트다운에 클릭 가능한 `[바로 시작]` 버튼 병기.

## 의심 5곳 판정 — 전부 OK

1. **지역 선택 세션 교체** — `beginStage` 가 `stageId` 설정 후 `session = null`, 다음 프레임에 `STAGES[stageId]` 에서 지갑·`waveTable` 을 새로 읽는다. 오버레이가 `hidden` 토글로 바뀌었어도 잔존 상태 없음
2. **정산식 연쇄** — 계산·연출 소유권 모두 OK. 단 `closeAtStageEnd` 경로의 notice 가 유실됨(001)
3. **추가매수 `MAX_POSITIONS`** — 표시와 차감이 같은 `snap.openCount` 에서 파생. 일치
4. **S-03 AUM** — `castSkill` 이 잔액 반환 → `useSkill` 단일 반영. 비율 분모·미리보기·비활성 판정이 전부 같은 값을 씀
5. **프레임 루프** — `loop.start()` 호출부는 `stage.ts:370` 단 하나
