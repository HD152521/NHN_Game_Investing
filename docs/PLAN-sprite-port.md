# PLAN — 클로드 디자인 스프라이트 이식

> 근거: `docs/design-reference/ticker-front-sprites.js` (클로드 디자인 프로젝트에서 추출)
> 작성 2026-08-01

---

## 0. 왜 이 계획이 필요한가

`src/battle/shapes/` 는 **아트 시트의 글로 된 묘사만 보고 도형을 새로 발명한 것**이다.
정작 디자인 문서 안에는 43개 스프라이트를 그리는 **실제 드로잉 코드**가 들어 있었는데,
HTML 태그를 벗겨 텍스트만 읽는 과정에서 `<canvas data-spr="...">` 43개와
그것을 그리는 24,913자 스크립트를 통째로 놓쳤다.

결과적으로 화면에 나오는 그림이 **디자인과 전혀 다르다.** 이 계획은 그것을 바로잡는다.

### 원본 구조 (이식 대상)

```js
PAL = { '.':null, '0':'#05070C', '1':'#070A12', '2':'#0F1524', '3':'#1A2236',
        m:'#7C89A3', w:'#E8ECF4', r:'#FF4D5A', d:'#B32330',
        b:'#2E86FF', n:'#1A4E9E', g:'#FFC53D', p:'#9B6BFF' }

mk(w,h) → { px, rect, disc, poly, outline, rim, g }   // g = string[][] 문자 그리드
allyRookie() → c.rect(...).disc(...).outline('0').rim('w').g
paint(canvas, grid) → 1픽셀씩 fillRect
```

**각 스프라이트는 `string[][]` 를 반환하는 순수 함수다.** DOM 의존이 전혀 없다.
색약 모드 매핑(`MAP.normal` / `MAP.cb`)도 원본에 이미 들어 있다.

### 스프라이트 43종 전량

| 그룹 | 키 | 개수 |
|---|---|---|
| 아군 | `tf-ally-01~03`, `tf-ally-parts` | 4 |
| 악당 | `tf-enemy-01~03`, `tf-enemy-air-01~02` | 5 |
| 타워 | `tf-tower-01~03` | 3 |
| 기지 | `tf-base-ally`, `tf-base-enemy`, `tf-boss` | 3 |
| 배경 | `tf-bg-r{1,2,3}-{far,mid}` | 6 |
| 발판 | `tf-gnd-r1~r3`, `tf-gnd-s1~s3`, `tf-gnd-slot` | 7 |
| 날씨 | `tf-wx-01~04` | 4 |
| 스킬 FX | `tf-fx-01~03` | 3 |
| 발사체 | `tf-w-01~04` | 4 |
| UI | `tf-ui-chart`, `tf-ui-btn`, `tf-ui-icons`, `tf-ui-reveal` | 4 |

## Step 1 — 스프라이트 생성기를 TypeScript로 이식

`ticker-front-sprites.js` 의 그리드 생성부를 `src/sprites/` 로 옮긴다.
**형태를 재해석하지 말고 좌표·색 문자를 그대로 옮긴다.** 이게 이 계획의 전부다.

- `PAL`, `mk()`(px/rect/disc/poly/outline/rim), 43개 그리드 생성 메서드
- 클래스가 아니라 **순수 함수 모듈**로. DOM·`document` 참조는 전부 제거
- 팔레트는 `src/design` 토큰을 참조하되, **원본 HEX와 일치하는지 테스트로 고정**
- 색약 모드는 원본 `MAP.cb` 를 `src/design` 의 색약 팔레트와 대조

**수용 기준**
- 43개 키 전부 존재하고 각각 `string[][]` 를 반환한다
- 각 그리드의 문자가 전부 `PAL` 에 존재한다(오타 0)
- `PAL` 12색이 `src/design` 팔레트와 일치한다
- 원본 JS와 동일 입력에 동일 그리드를 낸다(스냅샷 테스트)

**범위 밖**: 렌더링. 이 단계는 그리드 데이터만 만든다.

---

## Step 2 — 그리드 → 캔버스 렌더 파이프라인

매 프레임 픽셀을 찍으면 60FPS가 안 나온다. **오프스크린 캔버스에 1회 래스터화하고
이후에는 `drawImage`** 로 그린다.

- 모듈 로드 시 또는 최초 요청 시 그리드 → `OffscreenCanvas`(폴백: `<canvas>`) 1회
- 좌우 반전(적은 좌향)은 `drawImage` 시 `scale(-1,1)` — 그리드를 두 벌 만들지 마라
- 색약 모드 토글 시 캐시 무효화 후 재래스터화
- **프레임당 할당 0**

**수용 기준**
- 유닛 60체 + 타워 8기에서 프레임당 `drawImage` 호출만 발생(픽셀 루프 0회)
- 색약 토글 시 캐시가 갱신된다
- 캔버스 미지원 환경에서 크래시하지 않는다

---

## Step 3 — `src/battle/shapes/` 폐기 및 교체

새로 발명한 도형을 전부 걷어내고 이식한 스프라이트로 바꾼다.

- `draw-units.ts` / `draw-towers.ts` / `draw-structures.ts` 가 스프라이트를 쓰게 배선
- `src/battle/shapes/` 삭제
- `identity.ts` 의 `codeId`(A-01 등)와 스프라이트 키(`tf-ally-01`)를 잇는 매핑을 **한 곳에만** 둔다
- 실루엣 정합 테스트(rounded ⇒ arc 존재)는 픽셀 아트에 맞게 **재작성**한다 —
  `arc` 개념이 없으므로 다른 불변식(예: 진영별 외곽 곡률/각도 분포)으로 바꾸거나 폐기

**수용 기준**
- 화면의 유닛·타워·기지가 디자인 문서의 그림과 동일하다
- `shapes/` 참조가 0건 남는다
- 기존 테스트가 전부 통과하거나, 깨진 것은 이유와 함께 교체된다

**범위 밖**: 배경·발판·UI (Step 4~5)

---

## Step 4 — 배경 6장 + 발판 7종 배선

현재 `draw-background.ts` / `draw-ground.ts` 는 자체 구현이다. 스프라이트로 교체한다.

- 배경: `tf-bg-r{1,2,3}-{far,mid}` — 원경/중경 패럴랙스 2레이어
- 발판: 지역별 `tf-gnd-r1~r3` + 상태별 `tf-gnd-s1~s3`(정상/균열/함몰)
- 슬롯 데칼: `tf-gnd-slot`
- 가로 타일링 이음새가 보이지 않아야 한다

**수용 기준**
- 지역 3종의 배경이 서로 구분된다
- 발판 상태 3단계가 기존 판정(`src/ground`)과 연결된다
- 좌우 스크롤 시 이음새가 없다

---

## Step 5 — UI 4종 배선

- `tf-ui-chart` 차트 패널 프레임 · `tf-ui-btn` 예측 버튼 · `tf-ui-icons` 아이콘 3×2 · `tf-ui-reveal` 공개 연출 배경
- 시트 09 원칙: **프레임은 비우고 글자·숫자는 코드에서 얹는다**

**수용 기준**
- 차트 패널과 전투 화면의 톤이 이어진다 (아트 방향의 존재 이유)
- 아이콘 6종이 작게 봐도 구분된다

---

## Step 6 — 날씨·발사체 스프라이트로 교체

`src/battle/draw-weather*.ts` 와 발사체를 시트 스프라이트로 바꾼다.

- 날씨 `tf-wx-01~04`, 발사체 `tf-w-01~04`
- 판정 로직(`src/weather`)은 그대로 두고 **렌더만** 교체
- 스킬 FX `tf-fx-01~03` 은 Step 7의 트리거 결정 후 배선

**수용 기준**
- 날씨 판정 → 스프라이트 매핑이 4종 모두 연결된다
- 판정 순수 함수는 변경되지 않는다

---

## Step 7 — 스킬 2종: 게임 로직 추가 또는 제거 결정 ★ 기획 결정 필요

**현재 상태**: 게임에 스킬은 **1종뿐**이다 (`SKILL_COST = 200`, `castSkill`).
PRD FR-6도 "스킬 1종"이다. 그런데 시트에는 3종이 있고, 나는 이펙트 3종을 만들었다.
**`S-02 배당 살포`와 `S-03 서킷브레이커 실드`는 트리거가 없어 아무 데서도 호출되지 않는다.**

### ✅ 결정: **A — 2종을 실제 스킬로 구현** (2026-08-01, 기획자)

| 스킬 | 효과 | 재화 |
|---|---|---|
| `S-01` 공시 폭탄 | 광역 즉발 피해 (**기존**) | 골드 `SKILL_COST = 200` |
| `S-02` 배당 살포 | **아군 유닛 회복** | 골드 |
| `S-03` 서킷브레이커 실드 | **기지 앞 방어막 — 일정 시간 본진 피해 차단** | **AUM 소모** |

**`S-03`이 AUM을 쓰는 것이 핵심이다.** 시트 08이 이 스킬만 보라(`#9B6BFF`)로 지정한 이유가
"자금을 태워 시간을 사는 스킬임을 색으로 알린다"이다. 전장에서 AUM을 소비하는 유일한 경로가
생기면서 **매매 자원과 전투가 한 번 더 맞물린다** — 실드를 쓰면 그만큼 매매 원금이 줄고,
줄어든 원금은 곧 벌 수 있는 골드가 준다는 뜻이다.

**부수 작업**
- 비용·쿨다운·효과량 신규 상수 → PRD FR-6 개정 필요
- `S-03`이 AUM을 태우므로 **스테이지 게이트 밸런스 재검증 필수**
  (`stages.test.ts` R1 목표 −5%p 실패 / 목표 통과가 유지되는지)
- UI: 스킬 3종 버튼 + 쿨다운 표시. 재화가 다르므로(골드 2 / AUM 1) **색으로 구분**해야 한다

## 공통 제약

- 이식은 **재해석 금지**. 좌표와 색 문자를 그대로 옮긴다. 예쁘게 고치지 마라
- 색은 `src/design` 토큰 경유 (생 HEX 금지, `no-hardcoded-hex` 테스트가 막는다)
- 성능: 유닛 60체 + 타워 8기 60FPS, 프레임당 할당 0
- 판정(순수 함수)과 렌더 분리 유지
- 새 의존성 0개
