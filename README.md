# TICKER FRONT

> 정체를 가린 실제 과거 거래일 차트를 읽어 전쟁 자금을 만들고, 그 돈으로 일자형 타워디펜스 웨이브를 막아 지역을 점령하고, 클리어 후 그것이 어떤 회사의 어느 날이었는지 알게 되는 게임.
>
> — PRD §1.1

웹 (데스크톱 우선, 모바일 웹 대응) · Vite + TypeScript

```

             ★ 절대 삭제·수정 금지. 키잉을 다시 해야 할 일이 반드시 생깁니다
  cut/       마젠타 키잉·라인업 분할이 끝난 PNG (알파 포함)
  atlas/     아틀라스 패킹 결과 + 매니페스트 JSON — 빌드 산출물이므로 git 미추적
```

## 이미지 에셋이 아직 없는 이유

`assets/raw/`, `assets/cut/`, `assets/atlas/` 는 현재 **비어 있습니다** (`.gitkeep` 만 존재).

이미지 생성은 자동화된 빌드 단계가 아니라 **별도의 수작업 단계**입니다.
GPT Image / Flux / Midjourney / Ideogram 에 프롬프트를 넣고, 결과를 눈으로 판정하고,
게이트를 통과할 때까지 반복해야 하기 때문에 코드로 대체할 수 없습니다.

생산 순서는 [`docs/PLAN-art-production.md`](docs/PLAN-art-production.md) 를 따릅니다.
특히 **GATE-A (STEP 1, `E-01` 아군 유닛 3종)** 를 통과하기 전에는
다른 에셋을 뽑지 마세요. 스타일이 안 맞는 에셋 50장을 뽑고 버리는 것보다
캐릭터 1장을 20번 재생성하는 쪽이 빠릅니다.

그 전까지 게임 코드는 플레이스홀더 도형으로 진행합니다.
교체 비용을 낮추려면 `tools/asset-pipeline/` (STEP 8) 을 앞당기세요.

### 밸런스 검증 도구 2종

두 도구는 **서로 다른 질문**에 답한다.

```bash
npm run bot-sim                     # 경제 게이트 — "필요지출만큼 벌 수 있는가"
npx tsx tools/combat-sim/bin.ts     # 전투 게이트 — "그 돈으로 산 방어가 막는가"
```

현재 실측: 전투 클리어율(19 로드아웃 · 예산 100%) **R1 36.8% / R2 21.1% / R3 15.8%**.
경제 게이트 판별력(실제 1분봉 성질 기준) **최선 vs 최악 전략 격차 23~26%p**.

### 에셋 파이프라인

```bash
npm run assets:fixtures   # 합성 테스트 픽스처 생성
npm run assets:build      # raw + fixtures → 키잉 · 분할 · 정렬 · 패킹 → assets/atlas/
```

실제 에셋이 없어도 파이프라인이 검증되도록 **합성 픽스처**(`assets/fixtures/`)를 씁니다.
실제 AI 출력을 `assets/raw/` 에 넣으면 같은 이름일 때 `raw/` 가 우선합니다.

> 합성 픽스처는 배경이 완벽한 단색이고 프린지가 1~2px 입니다.
> 실제 AI 출력은 배경에 디더링이 섞이고 경계가 3~5px 에 림라이트까지 얹히므로,
> `--tolerance` 와 프린지 반경을 올려야 할 가능성이 높습니다.

### 알려진 제약

> 전체 목록과 코드 근거는 **[`docs/GAME.md`](docs/GAME.md) §13**에 있습니다. 아래는 요약입니다.

- **실데이터 미연결** — 차트는 전부 합성기(`generateChartSet`) 산출입니다. 그래서 **"진짜 그 날"이 존재하지 않고**, 공개 연출(FR-9)도 구현할 수 없습니다.
- **합성 차트에서는 매매 난이도가 사실상 없습니다** — 봇 실측상 최선 전략 ρ가 **+146%**, 클리어율 98~100%입니다. 실제 1분봉 성질(마팅게일)에서는 +2~3%로 떨어집니다. **실데이터로 바꾸면 밸런스가 통째로 흔들립니다.**
- **날씨 시스템이 화면에 뜨지 않습니다** — 판정과 렌더 양쪽 다 구현·테스트돼 있으나 셸이 `drawBattle`에 넘기지 않습니다.
- **jsdom 부재 → DOM 배선 테스트 0건** — click-path 감사가 찾은 결함 5건(CRITICAL 1 포함)이 전부 이 사각에 살아남았습니다. 핸들러 로직은 순수 함수로 뽑아 테스트합니다.
- **진행도 저장 없음** — 지역 잠금·경계도(heat)·부서 업그레이드·차트 도감이 전부 여기에 막혀 있습니다. `HEAT_PER_TERRITORY`(0.04)의 **런타임 효과는 현재 0**입니다.
- **세탁(z≈0 왕복)이 게이트를 통과합니다** — 목표 수익률이 ρ=0인 이상 구조적으로 막을 수 없습니다(PRD O-14). 남은 억제책은 보상 단조성과 `aumGate`(이익 청산 4회)뿐입니다.
- **UP(`#FF4D5A`) vs DOWN(`#2E86FF`) 명도 대비 1.08:1** — 색약 모드에서도 2.83:1 로 WCAG 3:1 미달입니다. `▲▼` 기호와 캔들 채움/빈칸은 보조가 아니라 **유일하게 신뢰 가능한 구분 신호**입니다.
- 스켈레톤의 팔다리 길이는 **임의값**입니다. 실제 스프라이트 비율로 재조정하지 않으면 팔다리가 분리돼 보입니다.
- 애니메이션 벤치마크는 **CPU 포즈 계산만** 측정한 값입니다. 실제 60FPS 리스크는 draw call 수(프레임당 680~1,360)이며 브라우저에서만 측정됩니다.
- **테스트 통과가 화면 동작을 뜻하지 않습니다** — `FakeBattleCtx`에 `drawImage`가 없어 다수 전장 테스트가 **폴백 경로**만 검증합니다. 스프라이트 경로를 건드렸다면 브라우저에서 확인하세요.

## 개발

Node 22+ / npm 10+

```bash
npm install
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | Vite 개발 서버 (기본 http://localhost:5173) |
| `npm run build` | 타입체크 후 `dist/` 로 프로덕션 빌드 |
| `npm run preview` | 빌드 결과 로컬 서빙 |
| `npm test` | Vitest 1회 실행 (118 파일 / 1,975 테스트) |
| `npm run test:coverage` | 커버리지 리포트 (목표 80%+) |
| `npm run typecheck` | `tsc --noEmit` 타입체크만 |
| `npm run bot-sim` | 경제 게이트 시뮬레이터 |

vitest 는 **node 환경**으로 돕니다 (jsdom 없음).
